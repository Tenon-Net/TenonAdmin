# ADR 0005 — 等保评估边界:内核是应用安全能力底座,不是定级对象

- 状态:**部分被取代**(2026-07-30) — 「以完整三级应用安全基线为产品目标」及「Level3 三期交付」由 [[ADR-0006]] 废止;本文件中**内核不是定级对象、不宣称已通过等保、网络/运维责任可出界**等边界表述仍有效,作历史评估存档
- 相关:`CONTEXT.md`「可选应用安全」;GB/T 22239-2019;[[ADR-0006]];[[ADR-0001]] / [[ADR-0002]] / [[ADR-0003]] / [[ADR-0004]] 同属决策存档

## 背景

TenonAdmin 是可分发的后台内核,消费者基于它承载自己的业务、数据和用户。直接问「TenonAdmin 满足几级等保」会混淆三个不同命题:内核是否提供应用安全控制、某个业务系统应定为几级、某个部署实例是否完成备案与测评。后两项都依赖具体业务和运行环境,不能从内核代码推出。

本次评估的目标不是给内核定级,而是回答:消费者建设等保系统时,身份鉴别、访问控制、安全审计、会话安全等应用层要求是否已由内核提供;消费者是否需要修改内核源码;哪些能力只需配置,哪些仍需外部实现或基础设施。

## 已确认决策

1. **TenonAdmin 内核不是定级对象。** 定级对象是实际承载业务的数据处理系统,其级别由受侵害客体与影响程度决定。因此不对内核宣称「已通过等保二级/三级」。
2. **内核按应用安全能力底座评估。** 评估采用「开箱满足 / 配置后满足 / 扩展后满足 / 内核缺口 / 非内核责任」五种结论,避免把存在接口或可选开关误写成已经满足。
3. **合规接入不应要求修改内核源码。** 生产系统应通过配置、既有 TryAdd 扩展点和宿主/基础设施接线完成安全建设。若一项通用应用安全控制必须 fork 内核才能实现,则记为内核缺口。
4. **网络与运维责任可以出界,但接口责任不能消失。** 防火墙、主机加固、数据库备份、集中日志平台等不由内核实现;内核仍需提供正确的日志、健康探针、密钥配置、代理来源、存储替换等接入能力。
5. **内核以三级的应用安全基线为产品目标。** 内核应将身份鉴别、访问控制、安全审计、数据保护和应用防护做成正式、可验证的能力;消费者主要完成部署接入与环境配置,不应为常规等保应用控制修改或 fork 内核源码。二级是该目标的自然子集,不是产品能力上限。
6. **生产环境提供显式的 Level3 强制安全档。** `TenonAdmin:Security:Profile=Level3` 在启动期验证三级应用安全基线的强制项,不合格即拒绝启动;不依赖业务方阅读文档后自行遵守。Development 不自动启用该档位,保留本地零配置与调试便利。
7. **Level3 以三条规则确定强制 MFA 账号。** 超级管理员始终强制;拥有高敏感操作权限的账号自动强制;管理员可以对任意用户显式要求 MFA。显式标记只能增加要求,不能覆盖自动强制。第二因子未启用、账号未绑定或验证通道不可用时拒绝登录,不得沿用当前「未绑定手机号即密码直通」的宽松语义。该设计适合仅有超级管理员和子管理员的常见后台,也能在角色和授权变化后保持正确。
8. **TOTP 是内核原生的默认 MFA 合规路径。** 用户使用兼容的认证器应用扫描绑定二维码,在密码校验后输入当前动态口令。TOTP 不依赖短信供应商;现有短信 MFA 保留为可选补充或恢复方式,但不作为 Level3 的唯一强制路径。实现必须同时提供一次性恢复码和受审计、受权限控制的第二因子重置流程。
9. **高敏感权限集合支持受控的页面维护。** 内核按路由权限码维护不可移除的默认集合;消费者可通过受权限保护的页面动态追加或移除自定义权限码,但不能移除或覆盖内核默认项。变更必须记录操作审计,并在下一次登录时参与 MFA 判定。该维护页面本身属于高敏感操作,Level3 下操作人必须已完成 TOTP。
10. **Level3 以一次性初始化授权完成首个超级管理员迁移。** 部署者经环境变量或密钥管理提供短时、一次性的初始化授权,仅允许首个超级管理员绑定 TOTP;绑定成功后立即失效。其他管理员不使用部署期后门,只能由已完成 TOTP 的管理员在后台受审计地发起绑定或重置。这样既避免启用后锁死管理员,也不保留长期绕过 MFA 的通道。
11. **Level3 对安全审计设置不可降级的最短留存和删除边界。** 操作、登录和异常审计日志至少留存 180 天;留存配置只能调长,不能调短。禁用人工一键清空,仅允许按策略分批清理已到期数据。审计导出、敏感日志查询和留存策略变更均需再次留痕。内核还必须提供可替换的审计外送接口,由消费者接入 SIEM、日志平台或 WORM 存储;集中化和防篡改存储的基础设施由部署方负责。
12. **Level3 强制安全 Cookie 会话模式。** 刷新令牌仅以 `HttpOnly`、`Secure`、`SameSite` 受控 Cookie 交付,不进入 JavaScript 可读存储;访问令牌仅在浏览器内存短暂保存,页面重载时由 Cookie 静默换取。该模式必须有 CSRF 防护。当前 `localStorage` 令牌模式保留给 Development 或显式降级场景,Level3 禁止使用。默认 Caddy 同源反向代理部署不改变拓扑;跨源部署必须显式配置可信来源、允许携带凭证的 CORS、Cookie 属性与 CSRF 校验。
13. **Level3 强制浏览器安全响应头与 HTTPS。** 生产入口必须使用 HTTPS,统一输出 HSTS、CSP、防嵌入、`X-Content-Type-Options: nosniff`、`Referrer-Policy: strict-origin-when-cross-origin` 与关闭非必要浏览器能力的 `Permissions-Policy`。CSP 默认采用同源白名单;消费者只能显式追加必要的可信来源,不得通过宽泛通配符回避策略。内核应提供中间件及 Caddy/nginx 宿主模板,使默认同源部署无需额外应用代码。
14. **Level3 对文件上传强制同步恶意文件扫描。** 内核提供可替换的 `IFileSecurityScanner`;上传文件必须在入库和对外访问前通过真实扫描器。扫描失败、超时或未配置均拒绝,不得先存后扫或降级放行。开发用空实现允许存在,但不能通过 Level3 启动校验。消费者只需提供 ClamAV、企业杀毒平台或对象存储扫描服务的适配器,无需修改内核源码;扫描结果、引擎版本和拒绝原因必须写入审计日志。
15. **Level3 强制密码与登录防护基线。** 新密码最小 12 位,须满足大写、小写、数字、特殊字符四类中的至少三类;不得复用最近 5 次密码。初始密码、管理员重置密码和密码变更后均强制首次登录修改;密码最长有效期 90 天。连续失败 5 次至少锁定 15 分钟。图形验证码在连续失败后成为强制门槛,不得被永久关闭或由运行时配置降级。Level3 启动期必须验证这些下限。
16. **Level3 提供版本化的数据保护密钥与字段加密契约。** 第一期先提供 `IDataProtectionKeyProvider` 与窄域的 `ISecretProtector`,保护 TOTP 秘钥、HMAC `ClientSecret` 和审计签名密钥;使消费者可接 KMS、密钥管理服务或受控密钥文件,主密钥不得硬编码在代码或业务数据库中。第三期扩展为通用 `IFieldProtector`:使用带版本号的认证加密和渐进重加密,将手机号、邮箱、外部身份令牌等纳入默认保护范围,消费者可通过属性或配置加入业务敏感字段。需要精确查询时另存不可逆规范化哈希索引。Level3 下缺少合格密钥提供方时拒绝启动;不自动加密全部业务字段,避免破坏既有查询、排序和兼容性。
17. **Level3 要求实际安全事件接收端。** 内核提供 `ISecurityEventSink`,产出结构化、可关联且已脱敏的安全事件,由消费者接入 SIEM、Webhook、邮件或告警平台并安排响应。连续登录失败或锁定、MFA 失败或重置、高敏感权限及其策略变更、管理员账号变更、审计策略变更、令牌重放、文件扫描拒绝和审计外送失败至少产生事件。内核负责事件产生、关联 ID、脱敏和审计;未配置实际接收端时 Level3 拒绝启动,不能把只写本地日志称为告警。
18. **Level3 对极高风险操作要求短时再次认证。** MFA 重置或解绑、管理员账号变更、高敏感权限和策略变更、安全档与密码策略变更、审计留存与事件接收端变更、数据保护密钥或密钥提供方变更、敏感审计导出、外部认证和文件扫描集成变更等操作,均要求当前用户再次完成 TOTP;必要时再输入当前密码。成功后只在约 5 分钟内对同类操作有效,过期、会话吊销或安全上下文变化即失效。
19. **国密兼容是独立于 Level3 的可选密码档。** 内核默认保持现代标准密码学;`Level3` 不自动等同于商用密码应用合规。需要国密的消费者显式启用 `CryptoProfile=GM`;该档位必须通过启动校验确认算法实现、TLS/证书路径和密钥来源均符合要求。密码算法实现保持可替换,支持 SM2/SM3/SM4 及国密 TLS 网关或证书体系,不要求消费者 fork 内核。
20. **Level3 的内核发布采用供应链质量门禁。** 正式发布生成 SPDX 或 CycloneDX SBOM,并扫描 NuGet、npm 与容器基础镜像依赖。PR 以告警反馈,不阻断普通开发;正式发布对未获批准的 Critical/High 漏洞阻断。无上游修复或不可利用时可建立例外,但必须记录理由、责任人和到期日,到期后重新阻断。发布包、镜像和 SBOM 提供可验证签名或构建证明,并向消费者提供当前版本已知漏洞与修复建议。
21. **安全事件以事务性 Outbox 可靠投递。** 安全动作和其结构化事件在同一数据库事务中持久化,由后台任务异步投递至 `ISecurityEventSink`。投递失败采用指数退避重试;持续失败后产生本地高优先级事件并使 `/health/ready` 不就绪。外部告警平台短时不可用不阻断普通用户请求,但高危安全配置变更的审计记录必须标明外送待处理状态,不能静默丢失。
22. **Level3 提供预检与证据报告。** 启动期校验不合格的强制项直接拒绝启动;同时提供仅限高敏感管理员访问的安全基线页面、可导出报告和供 CI/部署流水线消费的机器可读结果。报告覆盖 MFA、Cookie 会话与 CSRF、HTTPS/安全响应头、审计留存与外送、文件扫描器、事件接收端、密钥提供方以及 Redis 多副本条件等,仅输出通过/失败项、配置来源和修复建议,不得输出密钥、令牌、连接串或 TOTP 秘钥。该报告是上线门禁与等保测评材料的一部分,不替代正式测评。
23. **内核提供敏感数据展示与导出控制。** 字段加密保护存储,内核同时按敏感级别对查询结果默认掩码;只有显式的明文查看权限才能解掩。查看明文、批量导出和含敏感字段导出均写审计;Level3 下敏感导出还要求短时再次认证。消费者可通过属性或配置将业务字段标为敏感并选择掩码规则,无需修改内核。导出产物可选添加操作者、时间和追踪 ID 水印以支持追溯。
24. **Level3 必须显式启用,默认不启用。** 消费者须配置 `TenonAdmin:Security:Profile=Level3` 才进入强制安全档。自动启用会使既有项目仅升级内核就被 HTTPS、Cookie 会话、TOTP、文件扫描、审计外送和事件接收端等启动校验阻断,构成破坏性升级。Production 未启用时内核必须明确告警,预检报告标记为未满足三级应用安全基线,但不阻断现有项目运行。
25. **Level3 最小化定时任务的执行能力。** 默认仅允许受控的编译型任务;SQL 任务和外部 HTTP 任务必须由部署配置分别显式启用。创建、修改和执行这些高危任务仅限超级管理员,要求短时再次认证,并产生完整审计与安全事件。HTTP 任务继续强制域名白名单、禁跟随重定向和内网地址阻断;SQL 任务只能使用指定数据库连接,不接受任意连接串或凭据。
26. **Level3 的 MFA 恢复不得直接解除第二因子。** 用户可使用一次性恢复码恢复 TOTP。管理员发起 MFA 重置时只生成短时、一次性的重新绑定邀请,不直接解除 MFA。超级管理员的 MFA 重置须由另一名已完成 TOTP 的超级管理员批准;只有一个超级管理员时,只能使用部署期紧急恢复授权,并生成最高级安全事件。全程要求短时再次认证、完整审计和安全事件。
27. **Level3 按三期交付。** 第一期完成 `Security:Profile=Level3`、TOTP 与恢复、敏感权限策略、再次认证、安全 Cookie 会话与 CSRF、密码基线和预检报告;第二期完成 180 天审计留存、审计外送与 Outbox、安全事件、浏览器安全响应头、文件扫描器及敏感数据展示/导出控制;第三期完成字段加密与密钥轮换、国密密码档、供应链 SBOM/扫描/签名以及 Level3 部署与测评证据模板。每期都必须保留可验证配置、测试和消费者迁移路径。
28. **强制 MFA 用户不能用旧密码自行抢占首次绑定。** 启用 Level3 后,尚未绑定 TOTP 的强制 MFA 用户不允许正常登录,只能处于等待管理员发放绑定邀请的受限状态。首个超级管理员通过部署期初始化授权绑定;其他用户由已完成 TOTP 的管理员发放短时、一次性绑定邀请。此规则阻止仅持有旧密码的攻击者抢先绑定自己的认证器。
29. **TOTP 绑定邀请由内核生成、由消费者选择交付渠道。** 内核生成短时、一次性的绑定链接或二维码,管理员可在后台复制后通过既有安全渠道发给用户;已有 `IEmailSender` 或短信实现的消费者可以选择自动发送。内核不绑定具体通知厂商,邀请使用一次即失效,避免长期有效的绑定凭据。
30. **TOTP 绑定邀请采用可撤销的 15 分钟生命周期。** 默认有效期为 15 分钟;管理员可撤销未使用邀请;为同一用户重新发放邀请会自动使旧邀请失效。邀请只可完成 TOTP 绑定,不授予普通系统访问权限。使用、过期、撤销和重复发放均记录审计与安全事件。
31. **TOTP 恢复码每次生成 10 个、仅展示一次且服务端只存哈希。** 每个恢复码只能使用一次;使用后强制重新绑定 TOTP 并吊销该用户全部会话。生成新恢复码即废弃旧码。下载/查看恢复码、使用恢复码和重新生成恢复码均记录审计;Level3 下重新生成还要求短时再次认证。
32. **安全 Cookie 会话采用双提交 CSRF 防护。** 刷新令牌保持 `HttpOnly`;后端在登录或静默刷新时下发可读的随机 `csrf` Cookie;前端自动在全部写请求附带 `X-Tenon-CSRF` 请求头;后端对 Cookie 与请求头做常量时间比对。登录、刷新、登出、提权认证及 TOTP 绑定/恢复等所有状态改变操作都要校验,CSRF 值在登录、刷新、提权认证和登出时轮换。跨源模式仅允许显式可信来源携带该自定义头。
33. **Level3 统一以受保护的 Redis 保存安全状态。** 无论单实例还是多副本,登录锁定、限流、短时挑战和可失效的会话/权限缓存均使用 Redis,不允许退回进程内缓存。生产 Redis 必须启用认证和 TLS;不保存明文密码、TOTP 秘钥或刷新令牌。Redis 不可用时 `/health/ready` 失败;故障不得成为重启绕过锁定、限流或挑战状态的路径。
34. **程序调用 API 使用第三方接入应用,不复用管理员会话。** 接入应用是独立机器身份,可绑定最小接口权限、数据范围、有效期和可选 IP 白名单,支持禁用、密钥轮换、限流和独立审计。IP 白名单是可选加固项,未配置时不拒绝调用,但 Level3 预检报告必须明确提示来源未受限制。高敏感后台管理接口默认不授予接入应用,需消费者显式放行。浏览器用户继续使用安全 Cookie 会话,不提供长期个人 API Token。
35. **第三方接入采用 `ClientId + HMAC` 请求签名。** `ClientSecret` 仅在创建或轮换时展示一次。HMAC 验签需要服务端获取原始密钥,因此服务端以 `ISecretProtector` 做信封加密保存,不得错误地只存哈希。每个请求签名时间戳、随机数、HTTP 方法、路径和请求体摘要;服务端验证签名、时间窗口与随机数唯一性以抵抗篡改和重放。该协议由内核提供 SDK/示例和测试向量,使第三方无需使用管理员登录凭据。
36. **Level3 安全档只能经部署变更治理。** `TenonAdmin:Security:Profile=Level3` 只从部署配置或密钥管理读取,配置中心和管理页面不得将其改为 `None` 或在运行时关闭任一强制项。进入或退出 Level3 都需要部署变更并重启;降级必须产生最高级安全事件、完整审计,并在预检报告中持续标记。这样即使管理员账号被接管,攻击者也无法经页面静默关闭 MFA、审计留存或安全 Cookie 会话。
37. **第二期增加可验证的审计完整性链。** 操作、登录、异常和高危安全事件按独立账本分区(至少按日期)维护单调序号和前序哈希,避免所有请求争用一个全局尾记录;分区锚点与每日签名摘要通过 Outbox 外送,由 SIEM、WORM 或部署方独立保存。预检与安全页面可验证分区链是否断裂并报告具体时间段。该机制不声称阻止拥有数据库最高权限的人改数据,但必须让事后篡改可被发现。现有审计查询契约保持不变。
38. **Level3 对用户会话设置不可放宽的空闲与绝对时限。** 普通用户空闲 30 分钟、强制 MFA 用户空闲 15 分钟后会话失效;绝对会话最长 8 小时;访问令牌最长 15 分钟。安全 Cookie 中的刷新令牌轮换不得突破空闲与绝对时限。消费者可以配置得更短,不能在 Level3 下调得更长。前端在即将超时时提示续期;高危操作再次认证继续使用独立的约 5 分钟窗口。
39. **Level3 限制并发会话。** 强制 MFA 账号默认只允许 1 个活跃会话,新登录吊销旧会话并产生安全事件;确有多终端需求时最多放宽到 2 个,预检报告提示该风险。普通用户默认最多 3 个活跃会话。消费者可以将上限调低。用户可查看自己的当前会话和历史登录位置,并主动下线其他会话。
40. **Level3 自动治理长期未使用账号。** 普通账号连续 90 天未登录自动停用;强制 MFA 账号连续 60 天未登录先告警、90 天自动停用。超级管理员不自动停用以避免系统锁死,但在 60/90 天分别产生告警和高优先级安全事件。重新启用账号属于高危操作,要求短时再次认证、完整审计,并吊销全部旧会话与未使用绑定邀请。消费者可缩短期限,不能关闭该策略。
41. **分期功能发布与完整 Level3 声明分离。** 第一期和第二期可以交付、配置并验证相应安全能力,但在所有 Level3 强制项和预检项实现前,不得把任何中间版本表述为完整三级应用安全基线。Profile 的预检必须输出实现能力版本和未实现强制项;只有最终能力版本可以生成「完整」结果。

## 第一期实施冻结项

- **API 兼容:** 非 Level3 保持既有登录响应、请求体 refresh 和 `localStorage` 行为不变。Level3 才改为 `HttpOnly` refresh Cookie、内存 access token 和 Cookie 驱动的静默刷新;双前端必须同步迁移。
- **会话数据模型:** `SysSession` 增加绝对过期和最近活动时间。热路径使用 Redis 节流活动时间写入,不得每个请求写数据库;刷新不得突破绝对过期。
- **有效策略:** Level3 在 `ISecurityPolicyProvider` / 限流等读取层形成不可放宽的 effective policy。通用 `IConfiguration` 不能可靠判别配置来源,因此来源证明由宿主部署与 CI 预检负责;内核保证配置中心无法放宽已启用档位的下限。
- **存量迁移:** 新增 `LastSuccessfulLoginAt`。首次启用时,将现有启用账号以启用时刻作为闲置策略锚点并留审计,不按建号时间批量停用存量账号。
- **秘密与邀请:** TOTP 秘钥及 HMAC 密钥为加密态,恢复码和一次性授权只存哈希。绑定邀请是一次性 bearer 凭据,还必须校验目标账号当前密码后才允许写入 TOTP 秘钥。
