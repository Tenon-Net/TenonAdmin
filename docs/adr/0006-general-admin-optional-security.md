# ADR 0006 — 产品目标纠正：通用后台内核 + 可选安全能力（取代等保三级建设目标）

- 状态:**已采纳**(2026-07-30)
- 取代:[[ADR-0005]] 中「以完整三级应用安全基线为产品目标」及「Level3 三期交付」相关决策；0005 中「内核不是定级对象 / 不宣称已过等保」的边界表述**仍然有效**
- 相关:`CONTEXT.md`「可选应用安全」；历史评估稿 `docs/mlps-level3-kernel-plan.md`（已废止为建设路线图）
- 来源:2026-07-30 grilling（产品定位 → 一期处置 → 二/三期 → ADR → 合入策略 → 配置形状 → 第一刀范围 → TOTP 绑定模型）

## 背景

`feature/mlps-level3-phase1` 已实现等保三级应用安全**第一期**运行时（TOTP、Cookie/CSRF、预检闸门、强制 MFA 治理等），但**尚未合入 `main`、未进 CHANGELOG**。建设依据为 [[ADR-0005]] 与 `docs/mlps-level3-kernel-plan.md`，产品叙述是「内核以三级应用安全基线为目标，分三期交付」。

维护者重新评估后确认：TenonAdmin 的真实买家场景是**通用后台管理系统内核**（中小团队 / 内部系统快速搭建 RBAC 后台），**不是**合规/等保产品。在此定位下，完整三级路线图是错误的维护合同：会持续拉高双登录路径、启动 fail-closed、迁入仪式与文档表述成本，却没有对应的产品承诺对象。

本 ADR 冻结纠正后的产品决策，并规定未合入一期代码的落地形状。

## 决策

### 1. 产品定位：通用后台内核

- 主价值：身份、RBAC、多机构数据权限、字典/配置、日志、上传、可替换服务面，三行 `Program.cs` 可跑。
- 等保/测评**不是**产品目标；文档最多说明「应用层有可选用的安全加固」，**不得**承诺完整三级基线或测评通过。
- 内核仍不是定级对象（沿用 0005 边界）；不得表述「TenonAdmin 已通过等保」或「使用即过三级」。

### 2. 废止「完整 Level3 + 三期交付」

- **不再**以 `TenonAdmin:Security:Profile=Level3` 总档作为产品能力形状。
- **不再**维护第二期、第三期等保分期路线图（审计哈希链 / SIEM Outbox / 强制恶意扫描 / 字段加密 / 国密档 / SBOM 合规门禁等整包从承诺中移除）。
- 以后若实现某一安全项，一律按**独立小需求**评估（例如「加安全响应头」），不编号为 phase2/phase3，不绑等保条款清单。

### 3. 一期代码：瘦身后再合入，不原样合完整 Level3

未发版是改形状的窗口。`feature/mlps-level3-phase1` **不得**以完整 Level3 语义合入主线。

**保留，并降级为普通可选能力（去掉等保话术）：**

| 能力 | 说明 |
|------|------|
| 可选 TOTP + 恢复码 | 默认关；显式启用 |
| 可选 Cookie + 双提交 CSRF 会话 | 默认仍可为 localStorage 兼容模式 |
| 可配置密码策略、会话并发/空闲超时 | 可调严，不设 fail-closed 总档 |
| 高危操作再次确认（简单版） | 密码和/或 TOTP，短时窗口 |
| 窄域密钥保护 | TOTP 等秘密的实现依赖 |

**拆除或不再作为产品路径：**

| 能力 | 说明 |
|------|------|
| `Profile=Level3` 启动 fail-closed 整包 | 可选安全不得变成部署合同 |
| 生产未开 Level3 的合规告警 / 预检当测评材料 | 不做定级证明 |
| 强制 MFA 治理全集 | 高敏权限自动强制、闲置自动停用等重型剧本 |
| 部署期 InitGrant / 紧急授权 / 双超管批准重置 | 等保迁入仪式，非通用后台默认路径 |
| 管理员 15 分钟绑定邀请作为**唯一**迁入方式 | 见决策 5 |

### 4. 配置形状：独立可选开关，默认宽松

- **定稿键名表**见 [`docs/agents/security-optional-config.md`](../agents/security-optional-config.md)；绑定类型 `AdminSecurityOptions`。
- 核心产品键：
  - `TenonAdmin:Security:Totp:Enabled`（及 Issuer / ChallengeTtl / ReauthWindow / RequireForSuperAdmin）
  - `TenonAdmin:Security:Session:CookieMode`、`CookieDomain`、`IdleMinutesNormal`、`IdleMinutesMfa`、`AbsoluteHours`、既有 Mode/MaxConcurrent
  - 既有 `LoginLock` / `Captcha` / `RateLimit` / `SmsOtp` / `DataProtection` 保持独立
- `Profile=Level3` 与 `Security:Level3:*` 为**废弃键**；过渡期 helper 可兼容，禁止新部署依赖。
- **禁止**再引入「一键完整合规档」作为产品主路径。
- **默认必须保持零配置可跑**（SQLite、宽松密码策略、localStorage 会话等既有体验不被合入破坏）。
- 更安全行为一律**显式启用**。

### 5. TOTP 绑定模型：自助为主

- 用户（或管理员本人）在安全设置中**自助绑定** TOTP；绑定成功生成一次性展示的恢复码。
- 管理员可提供简单的「要求该用户启用 MFA」类开关（可选增强），**不**以邀请状态机为默认产品路径。
- 管理员清除用户 MFA、用户用恢复码重绑：保留**简单版**。
- 部署期初始化授权、15 分钟邀请链路、双人批准超管 MFA 重置：**第一刀不作为产品路径**（删除或冻结且不暴露）。

### 6. 第一刀合入完成定义

合入主线时必须同时满足：

1. 默认行为 ≈ 当前普通后台（非 Level3 强制语义）。
2. 打开独立开关后，可选 TOTP 与可选 Cookie/CSRF 在双前端可走通。
3. 仓库文档/ADR **不再**承诺三级基线或二/三期交付。
4. 新 ADR（本文）已合入；0005 标注被部分取代。

刻意留到后续（不阻塞第一刀）：重型治理代码的彻底物理删除、边角测试重命名、与等保相关的 agents 施工稿归档清理。

### 7. 决策文档治理

- 本 ADR 为安全产品方向的**现行**决策源。
- `docs/mlps-level3-kernel-plan.md` 改为**历史评估/废止路线图**，不得再当施工计划执行。
- `docs/agents/mlps-level3-phase1-*` 等施工稿仅作历史；新工作以本文与可选安全瘦身计划为准。
- `CONTEXT.md` 术语从「Level3 安全档 / 三期交付」迁到「可选应用安全」。

## 后果

- **正面**：维护合同与真实产品一致；避免无买家的合规工程吞噬通用内核迭代；未发版窗口可丢掉错误命名与 fail-closed 总档。
- **负面/成本**：一期完整 Level3 测试与仪式代码需瘦身或废弃，短期有重构量；若未来真有等保客户，需重新按合同做专项，而不是声称内核已是完整基线。
- **明确不做的对外表述**：任何版本在未另开合规专项并完成其范围前，不得宣传「完整三级应用安全基线」。

## 不在本 ADR 范围

- 具体配置键的最终拼写与 OpenAPI 路径重命名清单（实现 PR 内定，须符合决策 4–6）。
- 二/三期清单中某一薄片（如安全响应头）是否作为独立小需求排期——默认不排，有真实需要再开 issue。
