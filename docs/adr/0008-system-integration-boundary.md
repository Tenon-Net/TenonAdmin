# 第三方接入的框架边界与系统身份

2026-09-27 设计访谈确认：TenonAdmin 是通用框架，目标是让消费者基于既定接口规范、可复用接入机制和扩展点快速完成第三方对接，不必在每个项目重新设计通用接入方案。ERP、员工、BOM 和财务系统仅用于解释需求，不是框架的业务模型或交付对象。

框架负责通用接入规范和机制；消费者负责开放哪些业务能力、业务数据归属、字段映射及第三方协议适配。不能将通用认证、授权、调用审计等机制全部留给消费者重新实现；也不将行业连接器和可视化映射编排纳入首批范围。

首批后台自动对接采用独立系统身份，每个接入应用独立授权、独立撤销，不借用管理员账号或长期保存个人登录令牌。用户委托不在首批范围；现有外部登录 / SSO 仍是人的登录能力，本决定不改变 [ADR 0002](0002-batch-d-external-login-sso.md)。

首批面向内部系统及管理员批准的合作伙伴，不开放自助注册。授权覆盖可调用接口、业务数据范围和允许返回的字段；未授权默认拒绝，不能因系统身份缺少用户机构信息而放行全量数据。具体数据范围和字段白名单由消费者业务定义。

每类业务数据须明确权威来源，首批不提供任意双向覆盖与通用冲突合并。对于需要可靠投递的出站业务操作，区分本地业务成功与远端确认成功，支持持久化待处理、失败处理和人工恢复；超时视为结果未知，结合对方去重或查询能力处理，不能承诺仅靠本地重试就消除远端重复执行。周期性增量拉取作为允许分钟级延迟场景的推荐方式，不强制所有业务采用相同一致性要求。

## 已确认的交付边界

- 以官方可选模块提供完整默认实现，按需安装和启用，沿用框架服务可替换契约。具体包拆分依据实现依赖确定，不提前承诺多个包。
- 消费者编写明确的业务接口，通过少量声明接入认证、授权、限流、审计和接口文档；框架提供统一的分页、错误及版本约定，以及可运行示例和开发模板。不自动公开后台 CRUD 或数据库实体。
- 提供 Vue 和 React 两套管理界面，能力一致：接入应用创建与停用、凭据管理、接口授权、调用记录，以及可靠投递的失败记录和受控重试入口。业务数据范围仍由消费者显式接入，字段采用业务接口白名单，不建设通用可视化字段权限设计器。
- 首版同时提供普通出站调用和显式启用的可靠异步投递。普通调用提供 HTTP、凭据接入、超时处理及调用记录基础；可靠投递提供持久化、状态查询、重试和人工恢复，不要求额外部署消息中间件，不对所有操作自动重试。
- 提供一个完整的第三方适配示例，说明认证适配、字段映射、去重及结果确认的接入方式；不预装行业连接器。

## 认证、兼容与可靠性契约

默认认证采用 HTTPS + 每个接入应用独立的高强度 API Key，凭据仅创建时展示，服务端保存校验摘要，支持到期、撤销和新旧凭据短期并存轮换，日志不得记录凭据。相比首版自建 OAuth2 授权服务器，此方案减少部署与维护成本；代价是接入方需要保管和轮换长期凭据。保留认证扩展点，允许后续接企业身份平台；应用身份不替代接口授权和业务数据范围校验。

开放接口使用独立版本路由和 OpenAPI 文档分组，与后台接口共享业务服务，不直接复用后台接口作为外部契约。同一主版本保持兼容，破坏性变更进入新版本；统一错误、分页、时间和请求追踪约定。

可靠投递支持本地业务变更与投递记录同库同事务提交。每次逻辑投递使用稳定幂等标识，自动及人工重试均保持不变；对方支持去重或能查询确认结果时才允许安全重试，否则结果未知的写操作进入待核对状态。重试有次数和时间上限，耗尽后保留记录并支持告警及人工处理。保证记录可恢复、失败可追踪，不承诺任意第三方都能恰好执行一次。
