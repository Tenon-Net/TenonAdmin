# TenonAdmin 等保三级应用安全内核评估与建设计划

- 状态:已采纳,待实施(2026-07-28)
- 评估基线:GB/T 22239-2019《信息安全技术 网络安全等级保护基本要求》
- 决策记录:[ADR 0005](adr/0005-mlps-kernel-assessment-boundary.md)
- 术语:[CONTEXT.md](../CONTEXT.md)「等保应用安全能力」

## 一、结论

TenonAdmin 内核不是等保定级或测评对象,不能宣称「已通过等保二级/三级」。实际承载业务、数据和用户的部署系统才是定级对象。

就内核能力而言:

- 当前已经具备较完整的身份鉴别、RBAC、数据权限、会话吊销、登录锁定、限流和应用审计能力,可作为等保二级及部分三级控制的应用安全底座。
- 当前尚不能称为「完整的三级应用安全基线」。MFA、密码过期/历史等能力默认关闭,刷新令牌在前端 `localStorage` 中持久化,审计可人工清空,且缺少 TOTP、CSRF、安全响应头、恶意文件扫描、审计外送、防篡改证据、字段保护、安全事件、预检报告和供应链门禁等正式能力。
- 目标不是让消费者 fork 内核。通用应用安全控制由内核原生实现;短信、SIEM、WORM、KMS、恶意文件扫描器等通过稳定扩展点接入;网络、主机、数据库备份、机房和管理制度仍由部署方负责。
- 新增 `TenonAdmin:Security:Profile=Level3`,由消费者显式启用。默认不启用,避免既有项目升级即被阻断。Production 未启用时明确告警并在预检报告标记。

## 三、Level3 强制档

`Security:Profile=Level3` 仅从部署配置或密钥管理读取,不能从配置中心或页面降级。进入或退出均需要部署变更和重启。强制项不合格时拒绝启动;外部接收端持续故障时使 `/health/ready` 不就绪。

### 身份鉴别

- 原生 TOTP,兼容常见 Authenticator;短信作为可选补充,不作为唯一合规路径。
- 超级管理员始终强制 MFA;拥有高敏感权限的账号自动强制;管理员可对任意用户显式强制。
- 高敏感权限含不可移除的内核默认集合,页面只可维护消费者自定义追加项。
- 首个超级管理员使用部署期短时一次性初始化授权;其他用户由已完成 TOTP 的管理员发放 15 分钟一次性绑定邀请。
- 每次绑定生成 10 个仅展示一次、服务端只存哈希的恢复码。恢复后强制重绑 TOTP 并吊销全部会话。
- 超管 MFA 重置由另一名 TOTP 超管批准;单超管场景使用部署期紧急恢复授权并产生最高级事件。
- 密码最小 12 位,四类字符至少三类,最近 5 次不复用,最长 90 天,初始/重置后强制修改;失败 5 次至少锁定 15 分钟。

### 会话与高危操作

- refresh token 仅在 `HttpOnly + Secure + SameSite` Cookie;access token 只存浏览器内存。
- 双提交 CSRF:随机 Cookie + `X-Tenon-CSRF` 请求头,状态改变操作强制校验并按关键生命周期轮换。
- access token 最长 15 分钟;普通用户空闲 30 分钟、MFA 用户空闲 15 分钟;绝对会话最长 8 小时。
- MFA 用户默认单会话,最多可放宽到 2 个并告警;普通用户最多 3 个。
- 极高风险操作再次输入 TOTP,必要时再输当前密码;授权窗口约 5 分钟。
- 闲置普通/MFA 账号 90 天自动停用;MFA 账号 60 天先告警;超管只告警不自动停用。

### 审计、告警与证据

- 操作、登录和异常审计至少留存 180 天;只能调长;禁止一键清空,仅清理到期数据。
- 提供审计外送接口,接入 SIEM/WORM;提供 `ISecurityEventSink` 统一结构化安全事件。
- 安全事件以数据库 Outbox 同事务持久化、异步重试;持续外送失败导致就绪检查失败。
- 审计记录形成追加式哈希链,每日签名摘要外送;安全页面可验证断链时间段。
- 提供启动预检、安全基线页面、脱敏导出报告与 CI 机器可读结果。报告是测评材料,不替代正式测评。

### 应用与数据防护

- 强制 HTTPS、HSTS、CSP、防嵌入、`nosniff`、Referrer Policy 和 Permissions Policy。
- 文件上传必须经真实 `IFileSecurityScanner`;未配置、失败或超时均拒绝。
- 第一期提供 `IDataProtectionKeyProvider` / `ISecretProtector`,先保护 TOTP 秘钥、第三方 HMAC 密钥和审计签名密钥;第三期扩展为通用 `IFieldProtector`,支持认证加密、密钥版本和渐进轮换;精确查询使用规范化哈希索引。
- 敏感字段默认掩码;明文查看需专门权限;敏感导出需再次认证、审计和可选追踪水印。
- Redis 在单/多实例 Level3 中均强制使用认证与 TLS,不可用时不降级到内存。
- SQL/HTTP 定时任务默认关闭,显式启用后仍仅限再次认证的超级管理员操作。

### 第三方接入与发布

- 程序调用使用独立第三方接入应用,不复用管理员会话。
- 以 `ClientId + HMAC` 签名时间戳、随机数、方法、路径和请求体摘要;校验时间窗口和 nonce 防重放。服务端以 `ISecretProtector` 信封加密保存 HMAC 密钥,不错误地只存哈希。
- 接入应用绑定最小权限、数据范围、有效期、限流和独立审计;IP/CIDR 白名单为可选加固,未配时预检提示。
- 高敏感管理接口默认不授予第三方应用。
- 正式发布生成 SBOM,扫描 NuGet/npm/基础镜像,阻断未批准的 Critical/High 漏洞;例外带责任人和到期日;产物与 SBOM 提供签名或构建证明。
- 国密为独立 `CryptoProfile=GM`,不与 Level3 自动等同。

## 四、三期实施

### 第一期:认证、会话与预检闭环

- Level3 Profile 与启动校验
- 密钥提供方与窄域秘密保护(TOTP/HMAC/审计签名的前置依赖)
- TOTP、恢复码、绑定邀请、超管初始化/紧急恢复
- 高敏感权限集合、用户强制 MFA、再次认证
- 安全 Cookie 会话、双提交 CSRF、会话时限/并发/闲置账号
- Level3 密码与验证码下限
- 预检报告、安全基线页面和 CI 结果

#### 一期不可省略的实现边界

- 非 Level3 API、前端登录流和 `localStorage` 令牌模式完全兼容。仅 Level3 的登录/刷新响应切换为 Cookie refresh 与内存 access token;两套前端模板必须同时迁移。
- 新增 `AbsoluteExpiresAt`、`LastActivityAt` 和 `LastSuccessfulLoginAt`。活动时间使用 Redis 节流回写;首次启用以启用时刻初始化存量账号的最后成功登录时间,避免批量停用。
- Level3 必须通过读取层形成不可放宽的 effective policy,而不是只在启动时验证一次。`SysConfig`/管理页面不得放宽下限;配置来源的可信性由部署模板和 CI/预检证明,不能声称通用 `IConfiguration` 可自动识别其来源。
- `IDataProtectionKeyProvider`/`ISecretProtector` 是一期前置依赖。TOTP 秘钥和 HMAC 密钥加密保存;恢复码、邀请和初始化授权仅存哈希。绑定邀请还须校验目标账号当前密码,防止仅泄露邀请链接即可绑定攻击者的认证器。

### 第二期:审计与应用防护

- 180 天留存、禁用一键清空、按期分批清理
- 审计外送、安全事件、Outbox、就绪状态
- 按日期分区的审计完整性链与每日签名锚点,避免全局写入热点
- HTTPS 与浏览器安全响应头
- 文件安全扫描器
- 敏感数据掩码、明文权限、再次认证导出和水印
- 第三方接入应用与 HMAC SDK/测试向量

### 第三期:数据保护与发布安全

- 通用字段加密、查询哈希、密钥版本和渐进轮换
- `CryptoProfile=GM`
- SBOM、漏洞门禁、例外治理和产物证明
- Level3 部署指南、预检清单和测评证据模板

## 五、非内核责任与接口责任

| 事项 | 主要责任 | 内核必须提供 |
|---|---|---|
| 网络边界、WAF、IDS/IPS | 部署/运维 | 正确代理来源、真实 IP、限流和日志字段 |
| 主机、容器、数据库加固 | 部署/运维 | 非 root 镜像、健康检查、安全配置预检 |
| 数据库/文件备份与灾备演练 | 部署/运维 | 可替换存储、健康信息、迁移/恢复文档 |
| 集中审计与 WORM | 部署/运维 | 审计外送、Outbox、签名锚点和失败可见性 |
| KMS/HSM/国密证书 | 部署/密码基础设施 | 密钥提供方和密码档契约 |
| 恶意代码扫描平台 | 部署/安全平台 | `IFileSecurityScanner` 与 fail-closed 调用点 |
| 人员、制度、备案和第三方测评 | 系统运营方 | 预检报告、审计证据和配置说明 |

## 六、最终表述边界

完成三期并通过内核测试后可以对外表述:

> TenonAdmin 提供可显式启用并可验证的等保三级应用安全基线能力。消费者无需修改内核源码,通过配置及外部安全基础设施接入完成系统建设。

不得表述:

> TenonAdmin 已通过等保三级,或使用 TenonAdmin 的系统天然通过等保三级。

最终通过与否仍以具体定级对象的备案、建设整改和第三方测评结果为准。

## 七、分期发布边界

第一期和第二期可以先发布对应能力,但在全部强制项与预检项实现前,任何版本都不得表述为「完整三级应用安全基线」。预检报告必须包含实现能力版本和未实现强制项;只有最终能力版本才可输出完整结果。执行期间,HTTPS/HSTS 和代理安全响应头要用真实生产入口冒烟验证,不能只凭进程内配置或 `Request.IsHttps` 推断外部 TLS 已正确部署。
