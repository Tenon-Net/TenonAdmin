## 真实 bug(P0/P1,已修,带回归测试)

### F1 · P0 · 文件签名直链存储型 XSS
`SysFileController.View`(`[AllowAnonymous]` + inline)原样回吐上传时**客户端自报**的 `Content-Type`。后缀白名单默认不含 `.html`/`.svg`,**但浏览器认 Content-Type 不认后缀**:上传 `x.png`(过白名单)、其内容为 `<script>`、自报 `Content-Type: text/html`,匿名 view 即以 HTML 渲染;直链与 SPA 同源(默认部署 Caddy 同时托管 SPA 与 `/api`)→ 脚本读取 localStorage 里的 access/refresh 令牌。低权用户借此可窃取超管令牌 = 提权。全仓无 `X-Content-Type-Options: nosniff`。
**修**:view 改为**按后缀**解析权威媒体类型(仅 png/jpg/gif/webp/bmp/ico/pdf 允许 inline),其余一律 `application/octet-stream` + 强制另存;download 与 view 都加 `nosniff`。测试 `FileViewSecurityTests`。

### F2 · P1 · 机构改父可成环
`OrgService.UpdateAsync` 只挡 `ParentId == id`(父指向自己),不挡"父指向自己的后代"。A→B→C,把 A 的父改成 C 即成环 → 整支 A/B/C 在前端 `buildTree` 后脱离根、从机构树消失且**无法在 UI 修复**。数据范围的 `CollectDescendants` 有去重不会死循环,但树已损坏。
**修**:改父时 BFS 收 `id` 的后代集,新父落在其中即拒(`OrgInvalidParent`)。测试 `OrgCycleTests`。

### F3 · P2 · 配置 / 回收站写操作的审计**标题**可读性(非审计漏洞)
`ConfigController` 的 `batch`/`add`/`update`/`delete` 与 `RecycleBinController` 的 `restore`/`purge` 都无 `[OperationLog]`。
**自我纠正**:我起初把它记成"P1 无审计漏洞"——**这是错的**。`OperationLogFilter` 是 **opt-out**(`ShouldLog`:非 GET/HEAD/OPTIONS 且非匿名的动作一律留痕,`OperationLogCoverageTests` 已锁死),所以这些写操作**改前就已被审计**,只是标题回落为路由串(如 `PUT:/api/v1/sys/config/batch`)。真实严重度是 **P2**:给安全敏感 + 不可逆的动作补一个可读标题(改密码策略、彻底删除等,审计页一眼能看懂改了什么),不是补一个缺失的审计。
**改**:六个写端点加 `[OperationLog]` 描述性标题(无行为变化,纯可读性)。测试 `ConfigAuditLogTests`(标题为"批量修改配置")+ `RecycleBinTests`(硬删留痕)。

> 另:回收站三个接口此前**零测试**(危险面),本批补 `RecycleBinTests`:非法 type 拒绝、软删→列表→恢复回环、恢复撞唯一键报 `RecycleUniqueConflict`、硬删真删 + 留痕。这是本条真正有价值的部分。

## 原待确认项(已按你的决定处理)

### D1 · P2 · 前端 401 重放丢请求体 → **已修**
`web/src/api/client.ts` 刷新令牌后 `new Request(request)` + `fetch` 重放。`Request` 的 body 是一次性流、首次 fetch 即消费 → **恰在令牌过期那一刻的 POST/PUT** 重放时 body 为空(GET 无 body 不受影响,故一直没被发现)。
**修**:请求发出前 `request.clone()`(clone 会 tee body 流)存一份副本,重放时用未消费的副本;仅克隆非 GET/HEAD,副本以 WeakMap 键随请求回收。你选"先实测再定"——我判断这是确定性 bug(流一次性语义无歧义),直接修 + `?? request` 兜底,即便 openapi-fetch 的请求实例假设不成立也只退回原行为、不构成回归。

### D2 · P2 · v-auth 空权限集 fail-open → **已修(按推荐)**
权限码为空时不隐藏按钮:超管(无码)正确 fail-open,但普通用户若 `permissions()` 失败被吞成 `[]` 也放行全部按钮(服务端仍 403,非提权,只是 UI 谎报)。
**修**:auth store 加 `permissionsLoaded`,仅取码**成功**时置真;directive 未加载 → fail-closed 藏、已加载且空(超管)→ fail-open。不持久化,F5 后重新判定。

## 判定非问题(核查后排除——被否掉的怀疑与被证实的 bug 同样有价值)

- **回收站跨机构越权 restore/purge**:8 个回收类型(user/role/org/position/module/config/dict/menu)全部继承 `BaseEntity` 而非 `DataEntity`,即**不受机构数据范围约束**(系统表按 RBAC 权限管,本就是全局对象);且 `RestoreAsync`/`ListAsync` 的查询未 `ClearFilter<IOrgScoped>`。不存在跨机构越权。
- **匿名 `GET /sys/config/site` 泄漏配置**:`GetSiteInfoAsync` 只取固定白名单键(标题/副标题/版权/版权链接/验证码开关),不返回任意配置行。安全。
- **数据范围默认过宽**:`DataScopeProvider` 无角色→仅本人、有角色未配范围→仅本人、任一角色 All→不受限、否则取并集;`CollectDescendants` 带环去重。默认最窄,正确。
- **i18n 刷新后语言回弹**:`locales/index.ts` 写死 `zh-CN` 只是初值;`App.vue` 以 `watch(app.locale, …, { immediate: true })` 在挂载时立即应用持久化语言。不回弹。
- **账号枚举 / 登录耗时侧信道**:`AuthService.ValidateUserAsync` 对不存在的账号也跑一次等价代价的陪跑哈希,响应码与耗时均不可区分。已防。
- **越权提权 / 超管被锁死**:`UserService` 建号恒 `IsSuperAdmin=false`(不从入参取)、超管不可删/停/降权(Delete/BatchDelete/SetEnabled/Update 均有护栏)、密码哈希经 `UserItem` 投影不出接口、重置密码/停用/删除都吊销会话。已防。
- **`ErrorCode` ↔ i18n 文案漂移**:当前 45 个 MsgKey 的文案在 zh-CN/en-US **均存在,无漂移**。仍补一条守卫测试 `ErrorCodeLocaleConsistencyTests` 防未来新增错误码漏翻译。
- **写路径跨机构 IDOR**:`SqlSugarRepository` 对 `IOrgScoped` 实体在 `Update/Delete/HardDelete` 前有 `InScopeAsync` 守卫(全局过滤器只管 SELECT)。已防。
