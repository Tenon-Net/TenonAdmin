# TenonAdmin.Workflow Vue 预览版 — 测试人员使用说明

面向手工验收与探索性测试。覆盖 **Vue 前端**（`web/`）+ 默认样例宿主 `MinimalHost`。不要求读设计长文。

> 当前阶段：**M3a-2 Vue 预览**。React 工作流页尚未交付；AI 决策为 shadow-only（不自动推进审批）。默认 Outbox transport 是 `NoOp`（未接真实通道时外发消息会进死信）。

---

## 1. 本地怎么开

### 1.1 启动后端

在仓库根目录：

```bash
# 建议首次（或清库后）用固定密码，便于测试账号交接
TenonAdmin__Seed__AdminPassword='Aa123456' \
  dotnet run --project backend/samples/MinimalHost -c Release
```

- API：http://localhost:5100  
- 默认 SQLite：`backend/samples/MinimalHost/data/admin.db`  
- **仅在库里还没有任何用户时**会创建超管；已有库不会改密码。  
- 若忘记密码：停掉进程后删除 `data/admin.db`（及同目录 `admin.db-*`），再用上面的命令重启。

控制台看到 `Now listening on: http://localhost:5100` 即就绪。

### 1.2 启动 Vue 前端

另开终端：

```bash
cd web
npm install   # 首次或依赖变更时
npm run dev
```

- 前端：http://localhost:5175（本机）或局域网 `http://<服务器IP>:5175`  
- `/api` 已代理到 `5100`，浏览器只打开前端端口即可。  
- 开发服务器已 `host: true` 监听全网卡；若仍打不开，检查防火墙是否放行 **5175 / 5100**。

Windows 也可双击仓库根目录 `dev.bat`（会起后端与前端）。

### 1.3 登录

| 项 | 值 |
| --- | --- |
| 地址 | http://localhost:5175/login |
| 账号 | `superAdmin` |
| 密码 | 本次环境约定值（上文示例为 `Aa123456`） |

若登录页有图形验证码：看图片里的字符填入即可（开发环境 SVG 可直接辨认）。

登录后若出现应用选择页：
- **业务中心**：日常审批（发起 / 待办 / 抄送 / 我发起的 / 我已办的）  
- **系统**：流程治理（流程定义 / 监控 / 长期委托）与其它系统管理菜单  

普通员工角色应只授权业务中心下的审批菜单；不要授权「系统」应用下的流程定义/监控等。

## 2. 菜单与页面地图

| 菜单 | 应用 | 路径 | 测什么 |
| --- | --- | --- | --- |
| 发起流程 | 业务中心 | `/workflow/start` | 选已发布定义、填业务键/变量或内置表单后提交 |
| 待我审批 | 业务中心 | `/workflow/todo` | 同意/拒绝/退回/转办/委托/催办/加签/减签等 |
| 抄送我的 | 业务中心 | `/workflow/cc` | 抄送列表与已读 |
| 我发起的 | 业务中心 | `/workflow/mine` | 发起人视角、撤销等 |
| 我已办的 | 业务中心 | `/workflow/done` | 历史已办、拿回（满足条件时） |
| 流程定义 | 系统 | `/workflow/definition` | 列表、新建、发布、停用、进设计器 |
| 流程设计器 | 系统 | `/workflow/definition/designer?id=…` | 节点编排、Webhook/条件/并行、表单设计、保存发布（侧栏通常隐藏，从列表进） |
| 流程监控 | 系统 | `/workflow/monitor` | 全局实例监控（需监控权限；超管可用） |
| 长期委托 | 系统 | `/workflow/delegation` | 规则的增删改查（影响**新建**任务指派，一跳、禁止自委托） |
| 实例详情 | （两应用共用路由） | `/workflow/instance/{id}/detail` | 时间线、表单回放、当前办理人、操作入口 |

## 3. 推荐冒烟路径（约 30–45 分钟）

下列路径按依赖排序。每步「期望」不满足即记缺陷。

### A. 串行审批 + 抄送（基础闭环）

1. 进入 **系统 → 流程管理 → 流程定义 → 新建流程** → 填写名称 → **新建草稿**。  
2. 在开始节点下 **+**，添加 **审批** 节点：办理人选「指定成员」→ 选 `超级管理员`（或你准备好的测试用户）。  
3. 再加一个 **抄送** 节点（可选），指定抄送人。  
4. 顶部 **保存**，再 **发布**。列表中该定义应为已发布。  
5. 切换到 **业务中心 → 审批中心 → 发起流程**：选该定义，填业务单据键（可选）→ **提交发起**。应跳进实例详情。  
6. **待我审批**：打开任务 → **同意**。抄送人在 **抄送我的** 能看到并可标记已读。  
7. **我发起的 / 我已办的**（业务中心）与 **流程监控**（系统）能找到该实例，状态与历史一致。

### B. 条件分支（金额高低走不同路径）

1. 在 **系统** 应用新建定义：开始后加 **条件分支**；例如字段 `amount`，阈值 `10000`。  
2. 高额臂挂审批节点，默认臂可直接结束或挂另一审批。  
3. 发布后到 **业务中心** 发起两次：  
   - 变量 `amount=20000` → 应进入高额审批；  
   - 变量 `amount=5000` → 应走默认臂。  
4. 在实例详情核对走过的节点与办理人。

> 发起页若未绑内置表单，可用「键 / 值」变量对提交；键名须与条件配置一致（如 `amount`）。

### C. Webhook 节点（设计器配置）

1. 在 **系统 → 流程管理** 的设计器中添加 **Webhook**。  
2. 配置 URL、方法、超时、失败策略（失败终止 / 转人工）、可选请求头与最大尝试次数。  
3. **保存抽屉** → 定义 **保存** → **发布**。  
4. 刷新后重新打开节点，配置应完整回显。  

> 预览环境默认 **没有** 真实 HTTP Outbox transport：节点执行产生的外发可能进入 Failed 死信。验证「配置持久化 / 发布校验」即可；端到端投递需开发接好 transport 后再测。

### D. 内置动态表单

1. 在 **系统** 应用的设计器打开 **表单** 设计区，添加若干字段（文本、数字、日期/日期时间、单选、人员、附件等），设必填与范围。  
2. 审批节点可配置字段权限（隐藏 / 只读 / 可编辑）。  
3. 发布后到 **业务中心** 发起：发起页应按 schema 渲染；缺必填应挡提交。  
4. 审批时按权限看到可编辑或只读字段；详情页回放值正确。  
5. 日期时间应带时区信息保存（ISO 字符串）；可在不同时区浏览器各试一次展示是否合理。

### E. 高级审批动词（需多用户时更完整）

建议在 **系统 → 组织管理 → 用户** 再建 2～3 个普通用户：给员工角色只授 **业务中心 → 审批中心** 菜单；办理人也可先用超管临时指定做冒烟。

| 操作 | 入口（常见） | 关注点 |
| --- | --- | --- |
| 退回 | 待办详情 | 回到指定节点，历史有记录 |
| 转办 / 一次性委托 | 待办详情 | 任务办理人变更；与「长期委托」不是同一功能 |
| 催办 | 发起人或有权限者 | 通知/记录，不改变办理结果 |
| 撤销 | 我发起的 / 详情 | 仅允许的状态可撤 |
| 加签 / 减签 | 待办 | 会签名单变化；注意 CAS：并发两人同时改应一人成功 |
| 拿回 | 我已办的 | 仅「自己刚通过且下游尚未动作」等规则满足时可拿回 |
| 长期委托 | 系统 → 流程管理 → 长期委托 | 生效后**新产生**的任务可改派；不改已在办任务；禁止自委托 |

比例票签（`all` + 通过比例）若定义里配置了，用多个办理人验证「未达比例不往下走 / 达比例通过」。

### F. 并行分支

1. 在 **系统** 设计器添加并行拆分/合并结构，两臂各挂审批（不同办理人更佳）。  
2. 到 **业务中心** 发起后两臂应都能出现待办；全部完成后汇合再往下。  
3. 实例详情应能区分各臂 Token / 任务，互不串台。

## 4. 权限与账号建议

- **超管 `superAdmin`**：可进「系统」与「业务中心」，适合冒烟与排障。  
- **普通员工**：角色只勾选 **业务中心 → 审批中心** 下的发起/待办/抄送/我发起的/我已办的（及对应按钮）；不要勾流程定义、监控、长期委托，也尽量不要勾组织管理/系统运维。  
- **流程管理员**：在系统应用下授权「流程管理」目录（定义/监控/委托）。  
- **双人审批**：至少两个可登录账号，分别设为不同节点办理人；员工账号需能进业务中心。  
- 按钮级权限来自菜单种子（如加签、减签、拿回、outbox 重放）。非超管角色需在角色菜单里勾选对应按钮后才会出现操作。

## 5. 已知边界（测到了不要当回归缺陷）

1. **React 工作流 UI 未交付**（`web-react/` 无对等页面）。  
2. **Outbox 默认 NoOp**：未替换 transport 时外发会 Failed；**目前没有**完整的 Outbox 前端死信页（监控权限含 API，界面可能未暴露完整操作）。  
3. **AI Decision 为 shadow-only**：可有审计/元数据，但不会自动同意或拒绝任务。  
4. **浏览器 E2E** 重点覆盖登录、分支、基础动词、Webhook 发布；动态表单权限、并行多 Token、加减签/拿回/长期委托以本说明 + 后端回归为主。  
5. 所有写操作依赖 **RequestId** 幂等：同一请求重复提交应重放首次结果，不应双次推进。手工可用开发者工具看网络；自动化侧已有覆盖。

## 6. 缺陷怎么记

建议标题格式：`[Workflow][页面] 简述`。正文尽量包含：

- 环境：本机 MinimalHost + Vue / 浏览器与时区  
- 账号与角色  
- 流程定义名、实例 Id、任务 Id（详情 URL 可复制）  
- 复现步骤与期望 / 实际  
- 控制台或网络错误码（业务错误为数字 `ErrorCode`，前端有文案）
