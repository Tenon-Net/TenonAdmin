# 国际化

文案沿用 Vue 模板的写法：`{name}` 占位、命名空间划分、`ext` 自留地都一样。真正得改的是 react-i18next 的默认值，它有三处和这套文案对不上，`locales/index.ts` 逐条写死回来。另有一套 dayjs 的 locale 要单独注册，否则中文界面下的日期面板会露出英文。

## 怎么接起来的

react-i18next 靠 `src/locales/index.ts` 接进项目：

```ts
export const i18n = i18next.use(initReactI18next)
void i18n.init({
  resources,
  lng: useAppStore.getState().locale,
  fallbackLng: 'en-US',
  nsSeparator: false,
  interpolation: { prefix: '{', suffix: '}', escapeValue: false },
})
```

`initReactI18next` 把实例接上 React 的 hook（`useTranslation`、`Trans`）。初始语言 `lng` 直接读持久化下来的 `app.locale`，首帧就是上次那个语言，不会先中文再跳英文。当前语言缺哪个键，就回退到 `fallbackLng` 指定的 `en-US`。`zh-CN` 漏一个键，界面直接显示 `en-US` 里那句英文，不报错，也不露键名。

内置文案就两个文件，`locales/zh-CN.ts` 和 `locales/en-US.ts`，各自默认导出一个按命名空间分组的对象。没按组件拆，也没做按需加载。

`resources` 把两个词典包成 i18next 的形状，中间那层 `translation` 省不得：

```ts
const resources = {
  'zh-CN': { translation: withExt(zhCN, extMods, 'zh-CN') },
  'en-US': { translation: withExt(enUS, extMods, 'en-US') },
}
```

i18next 把第二层当命名空间。本模板只用一个命名空间，所有文案都挂在 `translation` 下。少了这层，`error`、`common` 会各自被当成命名空间，而默认命名空间 `translation` 空着，`t('error.auth.passwordWrong')` 会把这串点分英文原样吐出来，静态检查还一路绿灯。

### 三处默认值必须改写

i18next 的三个默认值和本仓库的文案不兼容，而且都是安静地错，所以在 `init` 里逐条写死：

- `interpolation.prefix/suffix` 改成单花括号 `{` `}`。文案沿用 vue-i18n 的 `{name}` 写法，i18next 默认认的却是 `{{name}}`。不改的话 `t('workbench.welcome')` 会带着花括号显示 `你好,{name}`。
- `escapeValue: false`。i18next 默认把插值结果做 HTML 转义（它本是给 `innerHTML` 用的），可 React 自己已经转义，再转一遍会把用户名里的 `&`、`<` 显示成 `&amp;`、`&lt;`。代价是插值结果只能进 JSX 文本位，别塞进 `dangerouslySetInnerHTML`。
- `nsSeparator: false`。默认的 `:` 分隔符会把含冒号的键从冒号处切成两半，前半当命名空间、后半当键，于是查不到。而[权限码](/zh/frontend-react/permission)正是 `GET:/api/v1/x` 这个形状，后端 msgKey 也可能带冒号。关掉之后，含冒号的键整条取值。

### 消费者的 ext 自留地

两个内置词典是上游的自留地。在 fork 上做业务，自己的文案别往里塞，放到 `locales/ext/<locale>/<模块>.ts`，默认导出该模块的键。`locales/index.ts` 用 `import.meta.glob` 把这个目录抓进来，按文件名当顶层命名空间深合并进词典，你什么都不用注册。这样你的文案就不会落在每次同步上游都冲突的那两个文件上。

深合并（不是整体覆盖）是必需的：后端 msgKey 是 `error.dict.typeNotFound` 这种嵌套键，消费者给自己的错误码补一句文案，只该补那一个叶子键，浅合并却会把整棵 `error` 子树连着兄弟键一起顶掉。这套约定和 Vue 模板逐字一致，但两边各存一份，共享层方向已经推翻，两个模板刻意自包含。约定细节见[双前端模板](/zh/guide/frontend-templates)和该目录的 README。

### antd 自带另一套 locale

antd 的空态、分页、日期组件有它自己的一套文案，和我们的 i18n 无关，得在 `App.tsx` 里跟着一起切：

```tsx
<ConfigProvider theme={themeConfig} locale={locale === 'en-US' ? antdEnUS : antdZhCN}>
```

`antd/locale/zh_CN` 和 `antd/locale/en_US` 驱动 antd 组件的内置文案，`locale` 从同一个 `app.locale` 派生。不切它，就是「中文界面配一个 `No data`」。所以有两套语言状态，都盯着 `app.locale`：一套是 react-i18next，驱动 `t()`；另一套是 antd 的 `ConfigProvider`，驱动它内部组件。

## 加一个翻译键

两个词典按功能命名空间分组：`common`、`app`、`user`、`menu`、`dict`、`org`、`role`、`log`、`error`、`recycle` 等等，和 Vue 模板同一套划分。两个真实例子：

```ts
// zh-CN.ts
user: { title: '用户管理', account: '账号' },
workbench: { welcome: '你好,{name}' },

// en-US.ts
user: { title: 'Users', account: 'Account' },
workbench: { welcome: 'Hello, {name}' },
```

加键步骤：

1. 找准命名空间（确实是新功能，才新开一个顶级命名空间）。
2. 在 `zh-CN.ts` 和 `en-US.ts` 里同时加，用同一条点分路径，插值占位符（`{name}`、`{count}`）也要对上。
3. 组件里 `const { t } = useTranslation()` 拿到 `t`，再 `t('命名空间.键')`；非组件上下文（`utils/` 里的函数）用 `locales/index.ts` 导出的 `t`。

视图里所有可见文本一律走 `t('...')`，不写死中文或英文字面量，这是硬规矩。

## 运行时切换语言

语言是一条持久化的 UI 偏好，落在 `stores/app.ts` 里：

```ts
export type Locale = 'zh-CN' | 'en-US'

locale: 'zh-CN' as Locale,
setLocale: (l) => set({ locale: l }),
```

组件里 `useAppStore((s) => s.setLocale)`、组件外 `useAppStore.getState().setLocale('en-US')`，调一下就更新 `app.locale`。整个 store 经 zustand 的 `persist` 存进 `localStorage`，键名 `app`，`locale` 在持久化白名单里，所以刷新后语言选择还在。

改一次 `app.locale`，两套 locale 一起翻，因为它们都从这一个源派生。`locales/index.ts` 在模块级订阅 store：

```ts
useAppStore.subscribe((s, prev) => {
  if (s.locale !== prev.locale) void i18n.changeLanguage(s.locale)
})
```

`app.locale` 一变就调 `i18n.changeLanguage`，驱动 `t()`；`App.tsx` 里的 `ConfigProvider locale` 同样读 `app.locale`，驱动 antd 内置文案。于是切一次语言，两边在同一次渲染里一起变。订阅写在模块级而不是某个组件的 `useEffect` 里，因为 i18next 实例本就是模块级单例，非组件上下文里的 `t` 也得跟着切。

后端错误码怎么落成 `error.*` 文案，这页不讲。那套映射是数字码 → `msgKey` → 翻译键，绑在响应契约上，见[对接后端](/zh/frontend-react/api-contract)。`locales/index.ts` 导出的 `te()` 也在那页细说，它挡住指向子树的键，让错误提示退回后端原文。

## 日期面板还要注册 dayjs locale

antd 的 DatePicker、Calendar 面板里的月份名、星期缩写、周起始日不归 antd 的 locale 管，归 dayjs 管，所以 `locales/index.ts` 顶部多一行：

```ts
import 'dayjs/locale/zh-cn'
```

`ConfigProvider locale` 只切按钮、占位符这类外壳文案；面板里的内容由 antd 的 picker 拿 locale 对象里的 `'zh_CN'` 去调 `dayjs().locale('zh-cn').localeData()`。而 antd 自己一行 dayjs locale 都不 import，dayjs 遇到没注册的 locale 名会静默回落到 `en`。漏掉这行的症状：中文界面下按钮、占位符是中文，面板里却是 `Jan`、`Feb`，星期从周日起。一页两种语言，而 tsc、lint、测试全绿，控制台一声不吭。

只需要注册，不需要全局 `dayjs.locale()`：picker 每次都显式 `.locale(...)`。`en` 是 dayjs 内置的，所以只补 `zh-cn` 一个。这一层是 antd 特有的，Vue 模板的 Naive UI 日期组件自带 date locale（`dateZhCN`、`dateEnUS`），不经 dayjs。
