# 国际化与错误码

> vue-i18n 的接入方式、加一个翻译键的日常流程,以及最容易踩坑的部分——后端错误码如何映射到前端 i18n 键。

## 概览

`src/locales/index.ts` 把 vue-i18n 接起来:

```ts
export const i18n = createI18n({
  legacy: false,
  locale: 'zh-CN',
  fallbackLocale: 'en-US',
  messages: { 'zh-CN': zhCN, 'en-US': enUS },
})

/** 供非 setup 上下文(工具函数)使用的翻译器。 */
export const t = i18n.global.t
```

Composition API 模式(`legacy: false`),默认语言 `zh-CN`,当前语言缺键时回退 `en-US`。全部文案就两个文件——`locales/zh-CN.ts` 与 `locales/en-US.ts`,没有按组件拆分,也没有按需加载。

`App.vue` 把 Naive UI 自己的 locale(驱动日期选择器、分页等内置文案)与 app 的语言保持同步:

```ts
const naiveLocale = computed(() => (app.locale === 'en-US' ? enUS : zhCN))
const naiveDateLocale = computed(() => (app.locale === 'en-US' ? dateEnUS : dateZhCN))

watch(
  () => app.locale,
  (l) => {
    i18n.global.locale.value = l
  },
  { immediate: true },
)
```

所以实际上有两套语言状态从同一个源(`app.locale`)联动:vue-i18n 的 `i18n.global.locale`(驱动 `t()`)和 Naive UI 的 `n-config-provider :locale/:date-locale`(驱动它内部组件的文案)。

## 加一个翻译键

两个文案文件按功能命名空间分组——`common`、`app`、`settings`、`login`、`module`、`menu`、`user`、`config`、`dict`、`org`、`file`、`notice`、`role`、`log`、`profile`、`error`、`recycle` 等等。两个真实例子:

```ts
// zh-CN.ts
user: {
  title: '用户管理',
  account: '账号',
  deleteConfirm: '确定删除用户「{name}」?',
}

// en-US.ts
user: {
  title: 'Users',
  account: 'Account',
  deleteConfirm: 'Delete user "{name}"?',
}
```

加键步骤:

1. 找准命名空间(确实是新功能才新开顶级命名空间)。
2. 在 `zh-CN.ts` **和** `en-US.ts` 里同时加,同一个点分路径,插值占位符(`{name}`、`{count}` …)也要对上。
3. 组件内用 `t('命名空间.键')`;非 setup 上下文(如 `utils/` 里的函数)用导出的 `t`。

[前端规范](/zh/standard/frontend) 把这条定成硬规矩:视图内所有可见文本走 `t('...')`,禁止硬编码中文/英文字面量。

## 错误码约定

这是最不直观、也横跨前后端两侧的部分。

后端从不下发本地化文案。每个业务错误都是一个数字 `ErrorCode`(`backend/src/TenonAdmin.Core/ErrorCode.cs`),每个枚举成员标注一个 `[MsgKey("...")]`——一个点分路径字符串:

```csharp
/// <summary>文件超过大小上限;args 可携带 maxSizeMb</summary>
[MsgKey("error.file.tooLarge")]
FileTooLarge = 44002,
```

`ErrorCodeExtensions.GetMsgKey()` 首次访问时反射一次(缓存进 `FrozenDictionary`),取出这个键。**如果某个码没标 `[MsgKey]`,会回退成 `error.code.{数值}`**——比如一个没映射的 `44099` 会产出 `error.code.44099`。这个兜底的意义是:漏标注不会直接抛异常,而是退化成一个还能定位问题的字符串。

前端的 `error.*` i18n 命名空间和这些点分路径逐一对应:

```ts
// zh-CN.ts
error: {
  _fallback: '操作失败,请稍后重试',
  file: {
    tooLarge: '文件超出大小限制',
    // ...
  },
}
```

`src/utils/error.ts` 是两边真正碰头的地方:

```ts
export function translateError(err: unknown): string {
  if (err instanceof ApiError) {
    if (err.msgKey && i18n.global.te(err.msgKey)) return t(err.msgKey)
    if (err.message) return err.message
  }
  if (err instanceof Error && err.message) return err.message
  return t('error._fallback')
}
```

`i18n.global.te(key)` 只是检查当前语言的文案里存不存在这个键,是纯本地判断,不涉及网络请求。所以一个 `FileTooLarge`(44002)的完整链路是:

1. 后端抛 `AdminException(ErrorCode.FileTooLarge)`。
2. 响应信封携带 `code: 44002`、`msgKey: "error.file.tooLarge"`,外加一段非本地化的 `message`(仅作调试兜底)。
3. `translateError` 判断 `i18n.global.te('error.file.tooLarge')` → `true` → 渲染 `t('error.file.tooLarge')` → `"文件超出大小限制"` / `"File too large"`。

**踩坑的具体样子**:假设新加一个后端错误码——`[MsgKey("error.file.duplicateHash")] FileDuplicateHash = 44007`——但没人在 `zh-CN.ts` / `en-US.ts` 里补上 `error.file.duplicateHash`。`i18n.global.te('error.file.duplicateHash')` 返回 `false`,`translateError` 就退到 `err.message`(后端那段非本地化的原始调试文案),要是连它也是空的,再退到 `error._fallback`。不会报错崩溃,但用户看到的是一段通用或语气不对的提示,而不是本该显示的那句。**加一个后端 `ErrorCode` 和加对应的前端 `error.xxx.yyy` 键,是同一次改动的两半**——只做了前一半的 PR 是不完整的。

## 运行时切换语言

`stores/app.ts` 把语言当作持久化的 UI 偏好来管:

```ts
export type Locale = 'zh-CN' | 'en-US'

state: () => ({ ...DEFAULTS, collapsed: false, locale: 'zh-CN' as Locale }),

actions: {
  setLocale(l: Locale) {
    this.locale = l
  },
}
```

调用 `useAppStore().setLocale('en-US')` 更新 `app.locale`;整个 store 经 Pinia 持久化插件存进 `localStorage`(键名 `app`),刷新后语言选择还在。`App.vue` 里那个 `watch(() => app.locale, ...)`(见上文)随后把这个值推进 `i18n.global.locale.value`,而 `naiveLocale`/`naiveDateLocale` 这两个计算属性也是从同一个 `app.locale` 派生的——所以 vue-i18n 的文案和 Naive UI 内置文案在同一次渲染里一起切换。
