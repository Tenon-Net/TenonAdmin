# README 写作分支

修改根目录 `README*.md` 时，在 [write-docs 入口](../../write-docs.md)的共同契约之后读取本文件。改正文时同时读取[声音](site-prose.md#三声音)、[标点](site-prose.md#六破折号)和[手感项](site-prose.md#八手感项)；改开头时再读[开头与划界](site-prose.md#四开头)。站点闸门、页间导航和站点自检不适用于 README。

README 帮助读者判断框架是否适用，并找到第一条可运行的接入路径。文档站负责展开配置、机制和排查过程。

1. 介绍先交代框架定位、适用项目和接入方式。三行核心调用旁给出完整示例的入口，方便读者在实际项目中放对位置。
2. 主要特点从业务场景讲能力与作用，例如客户列表的数据范围、文件存到对象存储、审批中的字段权限。技术名词跟随必要解释，标题直接表达能力。
3. 快速开始注明运行目录、环境前提、命令、密码来源和预期结果；仓库示例、NuGet 接入及独立业务示例的步骤分别交代。详细配置链接到对应站点页。
4. 功能表保持简短，可选包和启用条件写在能力所在行或紧邻段落。在线演示与当前开发分支、正式发布包的差异须按实际版本说明。
5. 界面预览使用真实截图、等比缩略图和点击原图链接。沿用现有每行两张的表格，配简短页面名称、可读的替代文本；新增时同步原图与缩略图。
6. 文档入口按读者要完成的任务组织，如接入、新增模块、部署与升级。已有深层文档保留为事实的维护位置，README 只给必要介绍和链接。
7. 以 `README.zh-CN.md` 为母版，同步 `README.md` 与 `README.ja.md` 的能力、条件、步骤、截图和链接目的；各语言保持自然表达。站点中英对齐的细则见[站点正文规范的「九、中英关系」](site-prose.md#九中英关系)。

以当前 `README.zh-CN.md` 的「介绍」「主要特点」「快速开始」和「界面预览」为参考。沿用其信息分工，具体措辞随内容变化。

完成时逐项核对：功能描述是否真实，限制是否在相关能力旁说明，命令能否按给出的前提执行，多语言事实是否一致，截图与链接是否有效。版本徽章和运行地址核对当前发布与实际配置，历史文字不能替代核验。

README 不在站点 prose 脚本的默认扫描范围，日文也不适用站点中英判据；人工校对上述项目。只修改写作规范和入口时，检查链接与 diff 即可；站点页的验证按[入口流程](../../write-docs.md#站点页面分支)执行。
