# 文档写作规范（Write Docs）

写或改 `site/` 下任何一页文档，先读这一份。中文是母版，英文是译文。规矩分两条车道：脚本判得准的进闸门，判不准的靠人判，两条道的判据都在下面。

## 先看诊断：机器感在哪

**这一节是病历，不是待办。** 下面三处已经清完（2026-07，四批施工），数字留着是因为它们解释了这份规范每一条的由来；照着它去找存量会找不到。当前状态见每行第三列。

经典机翻词汇标记从一开始就是零：「值得注意的是」「让我们」「首先、其次」「强大、优雅、灵活」全站 0 次。**改稿时不要猎词**，病根从来不在用词。

最后清掉的是分号那 136 处，过程值得记一笔，因为它是这份规范里唯一一次**推翻自己**的判断。

起初判「不治」，理由是[八、手感项](#八手感项)的「分号焊接」要的是拆句、不是换标点，怕换了字宽把该拆的句子焊得更死。真去看那 136 处的形状，理由塌了：

```
配了 `Seed:AdminPassword` 用配置值;没配则随机生成并在启动日志打印一次
不受限则整体恒真（不过滤）;否则 `CreateOrgId ∈ 机构集`
单实例请显式配 `0` 以示知情;k8s 可用 StatefulSet 的 Pod 序号注入
```

全是并列/对照分句对——**分号用对了，字宽写错了**。那是两件事：字宽归闸门，该不该拆句归人判，而且换成 `；` 不会让将来拆句变难。混成一件事，代价是全角逗号和半角分号并排站在同一个分句里。

**教训不是「当时判错了」，是「判之前没看数据」。** 凡是要给一批东西定去留，先把那批东西的形状拉出来看，再定。

贯穿三处的机理只有一条，也是这份规范的总纲：

> 机器的特征不是用词差，是同一个槽位永远同一个形状。

上一轮 `c7885b0` 就栽在这里。它重写了 `getting-started.md`，把首句的自称词从「本篇」换成「这页」，槽位原样留下，于是「这页带你把 TenonAdmin 内核跑起来」活到了今天。所以下面每条规矩都得回答一句：**你接下来最想怎么糊弄我，糊弄完为什么更难看。** 答不出来的条款还没写完。

这也包括这份规范自己。它给的范例是全文唯一具体的东西，照抄范例的句式，就是换个槽位再栽一次。见[范例是示范判断](#范例是示范判断不是示范句式)。

## 一、闸门

脚本在 `site/scripts/lint-prose.mjs`。它按 `zh/` 前缀分中英，必须在 `site/` 下跑：

```bash
cd site
node scripts/lint-prose.mjs zh/frontend/i18n.md   # 改稿时：只扫这一页
node scripts/lint-prose.mjs                       # 全站扫
node scripts/lint-prose.mjs --selftest            # 改脚本前先让它跑绿
```

**全站扫现在是绿的，请让它保持绿。** 它跑在 CI 里（`.github/workflows/docs.yml` 的 `lint` job，push 与 PR 都跑，PR 对 `main` 和 `dev` 都收），selftest 排在全站扫前面。因为闸门自己坏掉会静默放行一切，那比没有闸门更糟。

判据是**紧贴中文字符**，不是「出现半角」。`Result<T>`、`AddTenonAdmin()`、`TenonAdmin:Database`、`(v1.2)` 里的半角合法，脚本不碰。围栏代码块、行内代码、markdown 链接目标、HTML 注释先剥掉再判。

| id | 判据 | 施工前存量 | 后果 |
|---|---|---|---|
| `halfwidth-comma` | 半角 `,` 紧贴中文 | 1434 | 硬拦 |
| `halfwidth-paren` | 半角 `( )` 处在中文语境 | 465 + 后来补抓的 10 | 硬拦 |
| `halfwidth-colon` | 半角 `:` 紧贴中文 | 362 | 硬拦 |
| `halfwidth-sentence-end` | 半角 `?` `!` 收在中文句尾 | 7 | 硬拦 |
| `halfwidth-semicolon` | 半角 `;` 紧贴中文 | 136 | 硬拦 |
| `halfwidth-between-code` | 半角 `, ; :` 两侧是代码或全角标点，整行却是中文 | 84 | 硬拦 |
| `halfwidth-quote` | 半角 `" "` 裹着中文 | 45 | 硬拦 |
| `spaced-emdash` | 破折号两侧有空格 | 112 | 硬拦 |

| 破折号预算 | 散文位 > 2 的页 | 32 页 | 只打印 |

五处容易误会的实现细节：

- **有两条判据，不是一条。** 前几条逐字符判「紧贴汉字」；`halfwidth-between-code` 判的是「这一行是不是中文」，因为剥掉行内代码之后，`（见 `X.cs`）:` 的冒号两侧只剩全角括号和空白，逐字符那条够不着它。
  加这条之前先量了准确率：要求两侧**都**是全角标点或被剥掉的代码，实测 84 真 0 误。
  同一个扩判据的想法曾经在括号那条上被**否掉**：那次把全角标点算进语境，会连带拦下纯代码的表格单元格，4 真 5 误。
  **准确率是逐条量出来的，不能从「看着像违规」推出来。**
- **强调标记会挡住判据。** `**验证参数**(x)`、`**两端都要配**:` 里的半角，读者看得见、规则看不见，因为 `**` 打断了「紧贴」。脚本把标记**挪到前面**而不是原地抹成空白：长度与行号不变，被强调的文字与后一个字符恢复相邻。抹成空白就得给三条规则各加空白容差，而容差会顺带卷进几百处 `` `Result<T>`: 说明 ``，那是另一个决定，不该由这个补丁夹带。
- **首句认定含引用块与首个列表项。** 开篇写成 `>` 或 `-` 不豁免铁律。那本来是个后门，已经堵上。
- **自称词是全列封死的**：这页、本页、这一页、这篇、本篇、本文、本节、本指南；英文侧是 `This page / guide / section / document`。后四个中文词现在全站 0 次，正是 `c7885b0` 迁走的上一代用法，不封死就是一条免费返回原句的通道。
- **破折号只数散文位**，标签位和表格占位符不计。分类规则见[六、破折号](#六破折号)。

改脚本的纪律：**每条新规则必须同时加自检的正例和反例**，并跑一遍确认命中数非零。一条永不触发的规则比没有规则更糟，它让你跑一遍绿灯、带着违规发车。

不进闸门的两样，别再提议加：

- **开头段与 H2 的措辞重合率。** 这是 B 类朗读目录唯一可能机器化的地方，但可靠的判法要真分词，成本远超收益。B 类的防线是人判 + [自检清单](#十自检清单)第 3 条，不假装机器能判。
- **`§N` 内部引用。** 全站 2 处，`grep -rn '§' site/zh/` 就能拉出来，为两个实例造正则是过度设计。规矩归[八、手感项](#八手感项)：**`docs/rebuild-design.md` 不发布到站上，正文不得把读者指过去。** 当时那 2 处性质不同，正好当判据的例子：`auth-security.md` 的「(设计 §15)」是泄漏，读者点不开，已展开说清；`standard/backend.md:91` 的「关键取舍引设计文档节号」是给内核维护者写 XML 注释的规矩，不是让读者去翻，留下了。现在 zh 侧只剩后者一处，grep 出来是它就对了。

## 二、范围

`site/` 下每一页，中英两侧，写新页和改老页一视同仁。

**改一页就只验一页**（`node scripts/lint-prose.mjs zh/你改的那页.md`）。别因为在改 A 页，顺手把 B 页也「统一」一遍——那正是当初留下 4 处孤儿括号的动作。

**闸门的硬拦项不分你是重写还是只动一个词。** 标点是铁律，跟改动大小无关。

`site/zh/standard/commit.md` 是本站的样板页，写不下去的时候去读它。它没被任何一轮重写碰过：不是漏了，是它一开始就写对了。它全篇 0 个「你」，靠「两者面向的读者不一样」这种把读者拉进判断的写法照样让人感到在对话；它零处段末指路模具，而那正是别的页面机器感最重的槽位。

## 三、声音

先讲为什么，再让读者动手。这个口吻只管两个槽位：**每页的开头段**、**章节之间的过渡句**。进入具体步骤、表格、清单、API 参考，立刻切回紧凑。

「为什么」必须是读者能验算或能想象的东西：一条因果链、一个后果、一个他真会问的问题。看 `backend/data-layer.md` 这段的骨架：

> 低位固定 12 bit(机器 6 + 序列 6)不是随手选的:41+12=53,ID 恒小于 2^53,落在 JS `Number.MAX_SAFE_INTEGER` 内,前端按数字解析 long 主键不丢精度。容量为 64 台机器、单机单毫秒 64 个 ID。

链条短到读者能自己复算，结论在最后，参数在最后的最后。

### 教师口吻 ≠ 啰嗦

这轮改稿最大的风险，是从「机械的拗口」变成「絮叨的拗口」。判据不是「这句有没有信息量」。任何一条理由都有信息量，那条判据对每一句铺垫都判留，等于没判。判据是**读者的已知状态**，两问：

1. **这条理由说出来，读者会不会心里回一句「那当然」？** 会，就删。
2. **不给这条理由，他照着做会不会做错？** 不会，就删。

举例。`route-a.md` 说「内部系统通常不值得为前端单开一个进程」是必要的：读者真会以为前后端必须分开部署，不说他就走错路线。但假如再补一句「毕竟进程越少，运维越省心」，读者只会回「那当然」，那就删。

这一条对**朗读目录**同样成立，而且是它的死刑判据：「这页讲 A、B、C」删掉之后，读者少知道的只是目录，而目录就在右侧边栏里。**目录不算信息。**

三组现成对照：

| | 啰嗦 | 教师 |
|---|---|---|
| 报幕 | 「这页讲这条链路怎么搭起来、两个中间件为什么写成现在这样」 | 「链路只有这么长，难的是第二个中间件：令牌过期必须对业务代码完全隐形。」 |
| 缓冲 | 「很遗憾，出于安全原因，密码是无法找回的」 | `faq.md`：「找不回。密码写进库时就已经哈希,没有明文可捞。」 |
| 自我介绍 | `components/index.md`：「本站页面是精选速览」 | `pro-table.md`：「逐个 prop 的完整清单在包的 README，这里不重复。」 |

「找不回。」三个字独立成句。机器写作最舍不得的就是这种短句，它总想先铺垫。

### 教师槽位也有配额

授权了教师口吻，就得给它上限。否则 10 个 H2 的页面能长出 9 句合法的过渡，每句单独看都过关，累起来就是絮叨。

| 槽位 | 配额 | 口径 |
|---|---|---|
| 开头段 | ≤ 3 句、≤ 100 字 | **开头段** = frontmatter 之后、第一个 `##` 之前的正文。**句** = 以 `。？！` 收尾的算一句，`；` 不算。**字** = 剥掉围栏代码块与行内代码后的 CJK 字符数，不含标点、不含西文。A 类划界句[不计入](#a-类不吃开头段的配额)。 |
| 章节过渡句 | 一页 ≤ 3 处，每处 ≤ 2 句 | **一处过渡** = 紧跟在 `##` 或 `###` 之后、下一个代码块/表格/列表之前的那段散文。段落中间的句子不算过渡。 |
| 全页篇幅 | 增长 ≤ 10% | 分母是该页**剥掉围栏代码块后**的字符数。不足 1500 字符的短页改按绝对额度 +150 字符。 |

不给分母，`route-a.md` 这种代码占大头的页会被 10% 掐死，`i18n.md` 却毫无约束。量一下：

```bash
node -e "const s=require('fs').readFileSync(process.argv[1],'utf8').replace(/^\`\`\`[\s\S]*?^\`\`\`/gm,'');console.log(s.length)" site/zh/guide/deployment/route-a.md
```

### 受话人：读者得能感到有人在对他说话

`standard/backend.md` 全文 0 个「你」，所有句子要么无主语祈使，要么名词判断。教师口吻的物理前提是台下坐着一个人；没有受话人，「先讲为什么」就退化成念规格书。

但**别把这条做成配额**。`commit.md` 全篇 0 个「你」，却是全站最好的一页。它靠「两者面向的读者不一样」这种把读者拉进判断的写法，照样让人感到在对话。而且 36 个页首要是个个焊一个「你」，那本身就是新模具，正好撞在总纲上。

所以这是判据不是配额：**读者能不能感到有人在对他说话。** 最直接的办法是用「你」，不是唯一的办法。别为了凑一个「你」，改写一句本来就对的话。

「消费方」只指那个装了包的宿主工程，不指读者本人。判漂移看**指代**，不看顺不顺口：这句话里那个词指的是「读者本人」还是「宿主工程」？指读者本人却写成「消费方」，就是漂移。（`replaceability.md` 同页既有「消费方不 fork 就能替换任意一环」又有「逼你先把顶级目录迁走」，前一个指工程、后一个指人，混在一起读着就像两个人写的。）

## 四、开头

铁律：正文第一句不得以自称词开头（清单见[一、闸门](#一闸门)）。

但铁律只挡词，挡不住写出那个词的动作。真正要封死的是这个模具：

> `<自称词>` + 带你、帮你、讲 + H2 罗列

**自称词换成什么都判死。判 B 类看的是有没有复述 H2，不是看有没有「这页」二字。** 复述包括同义复述：`frontend/structure.md` 的「目录怎么分」对应 H2「目录结构」，一个字都没重合，照样是复述。判据是**读者读完这句，知道的东西是不是等于扫一眼右侧目录**。等于，就是 B 类。

### 四组对照

**纯朗读目录**（`frontend/i18n.md`，整个开头段就这一句）

```
改前  这页讲前端这套 vue-i18n 怎么接起来、日常怎么加一个翻译键、语言怎么在运行时切换。

改后  加一句「保存成功」，要动几个文件？两个：中文词典落一个键，英文词典落一个键。视图里
      从头到尾只有 `t('common.saveOk')`，一个汉字都不写死。换语言于是变成换词典，而每句
      文案也从此欠着两笔债。
```

底下三个 H2 的顺序复述，一字不差。读者读完它，知道的东西和扫一眼右侧目录完全相等。

**把承诺当尾注扔掉**（`guide/getting-started.md`，`c7885b0` 的产物）

```
改前  这页带你把 TenonAdmin 内核跑起来,拿到一个能用的令牌调通第一个受保护接口,再把它接进
      你自己的 ASP.NET Core 项目、起好前端模板、换掉默认数据库。全程零配置,不用先装数据库。

改后  你大概已经打开另一个窗口准备装数据库了。不用装。克隆完仓库直接 `dotnet run`，控制台
      会打出一串超管密码，浏览器就能登进去：SQLite 文件内核自己建，表 CodeFirst 自己长，
      配置一行没写。这是 TenonAdmin 的第一条承诺，值得先拿示例验一遍再谈别的。
```

全文最值钱的那句承诺被当尾注扔在句号后面，前面六个 H2 倒是念全了五个。

**标题式名词句**（`guide/deployment/route-a.md`）

```
改前  后端顺带托管前端。一个进程、一个端口、同源 —— 内部系统首选。

改后  一个进程，一个端口，前后端同源。路线 A 的全部内容就是这三句话，剩下的都是它的推论：
      CORS 不用管了，Cookie 不用管了，代理不用管了。内部系统多半到这里就够。要接的只有
      两件事：静态托管的两行代码，和上传目录的位置。
```

三个无主语短语用顿号串起来，再甩一个结论。「内部系统首选」是结论，不是理由。

**穿了教师外衣的目录**（`frontend/structure.md`，最值得警惕）

```
改前  在 `web/` 里动手之前,先认清目录怎么分、应用从 `main.ts`/`App.vue` 怎么装配起来、dev
      代理怎么连到后端。

改后  `main.ts` 只有十来行，但顺序不能动：Pinia 必须排在 router 前面，否则守卫读不到 store。
      `web/` 这一侧就是这个调性。没有脚手架魔法，也没有约定大于配置，想知道什么在哪、什么
      时候跑，翻文件就行。地基是目录和这段顺序，认全了后面几页才有地方落脚。

      设计上的取舍见[核心概念]；写页面的具体约定去[前端规范]。
```

它不带「这页」二字，铁律拦不住，但那三项正好是「目录结构、启动流程、Dev 代理」三个 H2。「在……之前，先认清」只是句式上像先讲为什么，实际什么理由也没给。这就是本轮最可能出的次品：把「这页讲 A、B、C」改成「在动手之前，先认清 A、B、C」，正则鼓掌放行，篇幅还涨了。

最后那两句是 A 类划界，**不占开头段配额，别顺手删掉凑字数**。

### 范例是示范判断，不是示范句式

上面四组的改后，形状必须各不相同：设问作答、预判读者动作后否定、心智模型先行、从一个具体细节切入。这不是巧合，是硬要求。

**逐字复用范例的骨架视同违规。** 具体点名：「代价是……」「先……再……」「没有脚手架魔法」「……的全部内容就是这三句话」，这些是这四组各自的一次性写法，不是模板。

理由回到总纲：范例是这份规范里唯一具体的东西，其余都是禁令，人会照抄具体的那个。四组要是同一个骨架，16 页开头就会长成同一个样子。上一轮只换自称词、槽位留下；这一轮换了槽位、形状留下，退化程度一模一样，只是更难被正则抓到。

### 四种合格的起手式

同一目录下相邻页面不得连用同一种：

| 起手式 | 本站实例 |
|---|---|
| 读者当下的状态 → 一个他没意识到的前提 → 抽掉它 → 逼出问题 | `deployment/index.md`：「你已经用 `dotnet new tenon-app` 在本地跑通了……`npm run dev` 一切正常,是因为 Vite dev server 把 `/api` 反代到了后端……这层代理只在开发期存在。」 |
| 设问立靶，当场作答 | `backend/data-scope.md`：「它回答一个问题:同样的接口、同样的 SQL,不同用户看到的行为什么不同?」 |
| 先问自己一个问题，按读者意图分叉 | `guide/business-module.md`：「先问自己一个问题:这张表需不需要按机构做数据隔离?」 |
| 处境 → 一句话心智模型 → 划界 | `components/pro-table.md`：「几乎每一张列表页都是同一张表……它的模型只有两件东西」 |

设问必须是读者真会问的。自问自答的伪问题比朗读目录更糟。

## 五、「这页」：A 类留，B 类删

| | A 类（划界） | B 类（朗读目录） |
|---|---|---|
| 干什么 | 跟兄弟页面分工，把读者推去别处 | 把底下的 H2 复述一遍 |
| 有没有去处 | 有：带链接、带摘要，读者据此判断要不要跳走 | 没有：读者往下滚一屏就再读一遍 |
| 处理 | 保留 | 删 |

`components/icon-picker.md` 同一段里两类并存，正好当对照：

```
删（B）  这页讲包本身:它的取值契约、怎么加图标集、怎么塞本地 SVG、文案怎么翻。
留（A）  图标在 tenon 应用里怎么统一注册、`AppIcon` 怎么在全站渲染,归 [外观与图标] 那页;
         这里不重复讲接入约定。
```

**按句删，不按页删。** `frontend/routing.md` 的开头段里，全站最好的钩子、一句 A 类划界、一句 B 类目录挤在一起。

### A 类不吃开头段的配额

A 类撞上首句铁律时，铁律优先，**把划界挪到开头段末尾，但它不计入 ≤ 3 句 / ≤ 100 字**。不豁免的话，带一句划界的页面几乎不可能达标，你就会去删 A 类凑配额，那正好把导航删光。

`guide/sync-fork.md` 的「本页只针对一种情况:你 fork/克隆了整个 `Tenon-Net/TenonAdmin` 仓库……」内容是对的，位置是错的：

```
改后  前端没有可 npm 安装的包，所以 fork 整个仓库、把 `web/` 当自己的起点，是官方支持的路径。
      升级于是不再是改一个版本号：上游的修复要靠 git 合并拉进来，而你自己这几个月的改动就
      躺在同一批文件里。

      下面这套流程只针对这种情况，目标是两边都保住。
```

### A 类自己也会长成模子

8 篇里 4 篇的划界句用同一个模板「这页只管 X」：`api-contract`「这页只管码到键这一段映射」、`request`「这页只管到 `client.ts` 为止」、`routing`「这页只管路由怎么建、页面怎么缓存」、`portal-guards`「这一页只管门户进哪个应用的决策」。单看每句都合格，连起来读就露馅。保留 A 类的功能，禁止固化它的形式：

| 写法 | 例 |
|---|---|
| 「这页只管 X」 | 一个目录内最多 1 页 |
| 并进导航句 | 「错误键怎么加归 [国际化] 管，这里只到码、键这一段为止」 |
| 从读者视角划 | 「要是你找的是怎么加一个新语言，去 [国际化]」 |
| 否定式 | 「怎么加键这页不讲，那是 [国际化] 的事」 |

校对时按目录横向扫句式分布，不是逐页看。

## 六、破折号

施工前 315 个，平均每页 9 个；现在全站 12 个，无一页超预算。目标是**散文位**每页 1 至 2 个。先分三类，不然额度算错，会把好好的定义列表改坏。

| 位置 | 形状 | 处理 | 计额度 |
|---|---|---|---|
| 占位 | 表格空单元格 `\| —— \|` | 不动 | 否 |
| 标签位 | `**术语**——释义`、`` `代码`——释义 `` | 机械换成 `：` | 否 |
| 散文位 | 句子中间 | 重排句子 | 是 |

**标签位按形状判，`**粗体**` 和 `` `行内代码` `` 一视同仁。** 实测全站列表项的标签位 100% 带这两种标记之一，零个裸术语；裸术语只在表格单元格里出现，全站 2 例（「自定义指令——」「小型初始化工具——」）。所以裸术语只对表格开放。表格必须**按单元格**判而不是按行：表格里既有 `` `vite`——dev server `` 这种标签，也有整段解释性长句，后者住在表格里也依然是散文。

全站 28 个标签位，`appearance.md` 一页占 8 个（原语、角色令牌、度量、阴影……）。把它们算进额度，那页会逼着你去改根本没毛病的定义列表：配额满足了，好东西改坏了。

标签位实例（`guide/sync-fork.md`）：

```
改前  - **`main`**——只承载发布。每个提交都对应一个已打 tag、已发布的版本(`v0.1.0`……)。
改后  - **`main`**：只承载发布。每个提交都对应一个已打 tag、已发布的版本（`v0.1.0` ……）。
```

### 散文位：重排三步法

你接下来最想干的事，是写个 sed 把 `——` 全换成 `，`，跑完闸门全绿。别干。破折号在这批文档里普遍顶替了本该写出来的逻辑连词；换成逗号，逻辑关系就从「被隐含」降级成「被抹掉」，句子变成没有主张的流水账，读着比原来更像机器。**连词缺失恰恰是机翻的典型特征。**病根不是标点偏好，是不想费劲判断前后两句到底是什么关系。

1. 问这个破折号在替哪个连词：所以、因为、也就是说、换句话说、反过来。
2. 把那个连词**写出来**，另起一句。
3. 只有在连词写出来反而累赘时（纯同位语解释），才降成逗号或全角括号。

```
改前  ……照样复用同一个组件对象——`keep-alive` 的缓存条目原封不动,不会被逼着重新挂载。
及格  ……照样复用同一个组件对象，`keep-alive` 的缓存条目原封不动。
合格  ……照样复用同一个组件对象。也就是说，`keep-alive` 的缓存条目原封不动。
```

范例里的行内代码一个都不许丢。`AddTenonAdmin()` 掉了反引号，它的半角括号就落进硬拦，你会被闸门逼着改成 `AddTenonAdmin（）`，闸门于是亲手把代码标识符改错。

三组散文位对照：

```
结论补原因（backend/data-layer.md）
改前  `ISqlSugarClient` 以 `SqlSugarScope` 形态注册为单例——这是 SqlSugar 官方推荐的线程安全
      形态(内部按线程建 Client)。
改后  `ISqlSugarClient` 以 `SqlSugarScope` 形态注册为单例，这是 SqlSugar 官方推荐的线程安全
      形态，它内部按线程建 Client。

结论补后果（guide/replace-service.md）
改前  写在 `AddTenonAdmin()` **后面**,内置实现已经占了坑,你的 `TryAdd` 会被跳过——不报错,
      但替换没生效。
改后  写在 `AddTenonAdmin()` **后面**，内置实现已经占了坑，你的 `TryAdd` 会被跳过。它不报错，
      替换却没生效。

跳转指引（guide/deployment/index.md）
改前  配了 Redis 却不显式给它会直接拒绝启动——详解见[容器化与多副本]。
改后  配了 Redis 却不显式给它会直接拒绝启动。详解见[容器化与多副本]。
```

### 留下的那 1 至 2 个，判据

不是「揭示」「悬念」这种感受词。每个人都会觉得自己那 9 个都在揭示，那样额度等于没设。判据是**排除式**，逐处对照：

> 破折号后半句必须是读者读到前半句时**预期不到**的事实，且删掉它，前半句仍是完整判断。
>
> **凡是破折号后面能填上「因为、所以、也就是说、例如、详见、即」的，一律不算揭示**，按三步法重排。

自检动作：对每个保留的破折号，写出后半句为什么读者预期不到。写不出来，那就是原因或举例，重排。

范本（`frontend/routing.md`，全站最好的一句）：

> 你在菜单管理里加一条菜单、填好组件路径、保存,它就成了一个能点进去的页面——这中间没有一张你手写的路由表。

填不进任何连词，才是揭示。

页尾导航段、纯罗列的夹注、交叉引用指针一律不得用破折号：夹注改全角括号，罗列改冒号或拆句。`portal-guards`、`api-contract`、`routing` 三篇把仅有的额度烧在页尾报路名上，正文里真正需要停顿的地方一个都不剩。校对顺序据此定：**先清标签位和页尾，额度自然腾出来。**

写法：无空格 `——`，禁 ` —— `（闸门 `spaced-emdash` 硬拦，全站 112 处存量）。

## 七、标点铁律

中文正文全角化。豁免的判据是**紧贴中文**，不是「出现半角」：`Result<T>`、`AddTenonAdmin()`、`TenonAdmin:Database`、`(v1.2)` 里的半角合法；围栏代码块、行内代码、markdown 链接目标、HTML 注释一律先剥掉再判。

**本规范里的正则和代码片段不参与全角化。** v1 草稿在这里栽过：它给闸门补的正则里，分隔符写成了全角竖线 `｜`（U+FF5C），照抄进脚本不报错，只会静默失效。

| 半角 | 全角 | 备注 |
|---|---|---|
| `,` | `，` | |
| `:` | `：` | |
| `( )` | `（ ）` | 必须成对替换 |
| `" "` | `「 」` | 嵌套用 `『 』` |
| 汉字之间的 `/` | `、` | `/` 只留给代码标识符并列（`feat`/`fix`、`GET`/`POST`），全站统一无空格 |

引号选 `「」` 的理由：正文原本两套并存，实测 `「」` 只有 2 处、`""` 几十处、全角弯引号 0 处。选 `「」` 是因为它和 `""` 不会在视觉上混。

**这条在表里躺了整整四批才被执行。** 它一直写在上面，却没人给它写闸门规则，于是 45 处半角引号一路活到最后一轮，直到有人回头问「到底改好了没有」才被量出来。清完之后它立刻又暴露一处 `」:`——半角引号挡着，`halfwidth-between-code` 够不着那个冒号，跟 `**` 挡住判据是同一个盲区。**写进表里不等于治过了：规范里每一条，要么有闸门，要么有人拿脚本数过一遍，否则它只是一句愿望。**

三条容易漏的：

- **括号成对替换**：正则匹配 `\(([^)]*)\)` 整体换成 `（$1）`，不许对左右括号分别做单字符替换。`permission.md` 那 4 处孤儿就是上一次朴素替换的残骸：中文输入法按一次括号键出的是成对全角，不可能只出左半边。闸门 `mixed-paren` 现在盯着这个。
- **frontmatter 的自然语言字段也算正文**：`hero.text`、`hero.tagline`、`features[].title`、`features[].details`。`zh/index.md` 的 tagline 用全角逗号，底下 features 全用半角，同一个门面文件两套标点。
- **同一文件内标点体系必须一致**，这条比「用哪套」更重要。

## 八、手感项

脚本抓不到，改稿时逐句读。每条都有配额或判据，超了要能说出理由。

| 症状 | 病例 | 判据与改法 |
|---|---|---|
| 名词化判断句 | 「贯穿始终的设计约束是**可替换性**」 | 「是……约束、关键、核心」改动词句。把「是」后面的名词划掉，问「谁会因此做什么」，答不出就是空壳 |
| 长定语前置 | 「注册成挂在 `layout` 下、名为 `menu-${id}` 的路由」 | 「的」前面顶着 12 字以上就拆成谓语句；名词最多叠两层 |
| 括号夹注成瘾 | 「会话落库(源)+ 落缓存(热路径)」 | 一句 ≤ 1 个括号；括号内 ≤ 15 字、不含分号冒号和第二层括号；顿号列举中间不许插括号。**判去留看类型不看重要性**：是源码位置或配置键 → 留；是一句解释 → 提成主句或删。「重不重要」正是当初塞进括号的原因，拿它当判据等于没判 |
| 「不是 A，而是 B」 | 7 篇出现 11 次 | 每页 ≤ 2 次。把 A 删掉只留 B，句子照样成立就说明 A 是稻草人 |
| 「N 个 X」凑数 | 同页「三件事」「四个坑」「四个静默失败」「四个约定」 | 每页 ≤ 2 次，且数目须是封闭集合。同一批东西不要换着数 |
| 分号焊接 | 「主键统一 `Id`(雪花,AOP 填,不手赋);软删统一 `IsDelete`……」 | 一个 bullet 一条规则。写下 `；` 先自问能不能拆 |

| `→` 当连词 | 「A 上强退→DB 写了吊销」 | `→` 只进列表项的「条件 → 结论」和真正的流程链。散文里还原成「于是、结果」 |
| 每节都憋金句 | 7 页 40 余节，节节四到八字短句落地 | **金句** = 独立成句、不含代码标识符、意在收束而非给事实的短句（≤ 12 字）。一页 ≤ 2 节有。自查：把每节最后一句抽出来排成一列，符合这个定义的超过 2 条就删到 2 条 |
| 单句过载 | 一句 90 余字，破折号加两括号加分号齐上 | **又长又挤才算**：剥掉行内代码后 CJK > 45 字**且**停顿符号（`，；：——（`）> 2。两条都满足才判，见[下面的标定](#单句过载这条标定过一次) |
| 跨页复述 | 「限流桶」后果清单在 index、route-b、docker 三页各写一遍，条数措辞全在漂 | 只在最深那页讲透，其余一句带过并链接。写新页先搜关键词确认归属地 |
| 自我加冕 | 「招牌能力」「招牌特性」「整个内核的重点」三页争头牌 | 全站只留一处，给数据范围 |

### 「单句过载」这条标定过一次

原来写的是「≤ 45 字**或**停顿符号 ≤ 2」。全站 1536 个中文句实测下来，这个「或」把它自己废了：

| | 命中 | |
|---|---|---|
| 只超字数（> 45 字，停顿 ≤ 2） | 13 | |
| 只超停顿（≤ 45 字，停顿 > 2） | **299** | 字数集中在 26–35，其中 24 句不到 15 字 |
| 两者都超 | 91 | 分布在 26 页 |

误报率 74%，而且误报的是这种句子：

```
[19 字]  `scope`：可选，标注改动影响的范围（模块名、包名、目录名）。
[16 字]  跑起来后：`:5173` 是前端，`:5100` 是后端，`/health` 是探针，同源、无 CORS。
```

十几个字，干脆利落，拆开只会更糟。它们超标是因为**中文列举三样东西天然就是三个逗号**。而这两句分别出自 `commit.md` 和 `route-a.md`，是本规范亲自点名的两个正面样板。

**病根是把一种坏形状写成了两个独立触发器。** 病例原文「一句 90 余字，破折号加两括号加分号齐上」，描述的是**同一个**句子既长又挤；拆成「或」之后，那 299 句正常列举全被判死。真正该抓的是那 91 句：

```
[98 字 / 8 停顿]  拿到结果后守卫再决定去向：结果是选择器 → 去 X（本来就去 X 就直接放行，
                  因为渲染选择页要的数据这时已经齐了，不能弹回 Y，否则默认应用一旦设定就
                  再没入口去改它）；目标是 Z → 直接给出 W；其余情况 → 重新返回 V。
```

**这条留给后来人的不是新数字，是那 74%。** 给一批东西定配额之前，先把这批东西的分布拉出来看：配额卡在分布的哪个位置、误报的都是些什么。凭手感定数字，就会写出这条的原样——正文写着「这条能数，别靠语感」，数字本身却是靠语感来的。

## 九、中英关系

意思对齐，句法各按母语，不逐句译。

| | 中文 | 英文 |
|---|---|---|
| 地位 | 母版，先写 | 译文，后写 |
| 路径 | `/zh` | 根路径（默认语种，站点结构不动） |
| 破折号 | 散文位每页 1 至 2 | em-dash 是母语节奏，**不设限** |
| 句长 | ≤ 45 字 | 英语自己做主 |
| 全角化 | 全套 | 不适用 |
| 首句铁律 | 不得以自称词加罗列开头 | 不得以 `This page / guide / section / document` 开头 |

中文那句「登录之前,先弄清密码从哪来。」对应的英文，不是它的字面译文，而是英语里同样能把读者下一个疑问提出来的那句话。

**对齐的粒度是「事实与结构」，不是句子。** 具体三条：

1. 中文有的**事实**，英文一条不少；中文没有的，英文不许自己加。
2. **H2 / H3 的数量、顺序、划分**必须一一对应，代码块与表格的内容逐字一致。
3. 中文重排了一个句子，英文**不必**跟着重排，句子边界各按母语。但如果中文是把一条事实拆成了两句，英文得确认那条事实还在。

### 代码块里哪些字能译

这是英文侧唯一一处会**把文档变成假话**的地方，实测栽了五次。判据不是「里面是不是中文」，是**读者会不会拿它去比对源码、或者去 grep 输出**：

| 能译 | 不能译 |
|---|---|
| 注释（`//`、`#`、`/** */`） | 落进数据库结构的 `ColumnDescription` / `TableDescription` |
| ASCII 示意图的说明文字 | 日志模板：`logger.LogInformation("业务失败 {Code}…")` |
| 占位值：`"AdminPassword": "你的密码"` | 内核实际打印的控制台输出 |
| 示例组件的演示文案：`<n-button>新增</n-button>` | 任何被文中声明为「引自 `path/to/File.cs`」的字面量 |

最贵的一次是首启横幅：英文页把它译成了英文，可 `SuperAdminSeed.cs` 里那是段硬编码中文、**没有本地化路径**。英文页于是承诺了一个英文读者永远看不到的画面。同理，把日志模板译成 `"Business failure"` 之后，读者拿它去 grep 自己的日志，一条也搜不到。

**这类缺陷译得越流畅越难发现。** 唯一可靠的查法是拿文档去核源码，不是读译文。

## 十、自检清单

改完一页，按顺序过。

脚本判的：

1. `cd site && node scripts/lint-prose.mjs <你改的那页>`，硬拦零命中。
2. 破折号警告数在你能解释的范围内（标签位不算）。

人判的：

3. 第一句：读者读完它，知道的东西是不是等于扫一眼右侧目录？是就是 B 类，重写。
4. 开头段 ≤ 3 句、≤ 100 字（A 类划界句不算）。读者能不能感到有人在对他说话？
5. 搜 `——`：标签位换 `：`；散文位按三步法重排。留下的每一个，都要能说出后半句为什么读者预期不到。
6. 回头搜 `（`：破折号挤出来的解释是不是全逃进括号了？病灶换个壳不算治。
7. 数三样：「不是……而是」≤ 2、`见 [` ≤ 3、粗体 ≤ 3。
8. 把每节最后一句抽出来排成一列，金句超过 2 条就删到 2 条。
9. 每个「消费方」：它指的是宿主工程还是读者本人？指人就改。
10. 对字数：增长 > 10%（短页 > 150 字符），说明你在追加而不是替换，回头删朗读目录。原稿没有朗读目录可删的，说明这页本来就该短，别硬灌。
11. 数停顿符号：有没有单句超过 45 字、或一句里 `，；：——（` 超过 2 个的。
12. 英文侧：事实一条不少吗？H2 数量顺序对得上吗？有没有把中文的破折号限制和全角化误加到英文头上？

**改完一批之后，还要过这一条：**

13. **把这一批所有改完的开头段抽出来，排成一列读。** 前三个字的词性、收尾的句式、有没有「代价是」。但凡高度一致，就是模具，重写一半。这一条对应第 8 条（节尾金句排一列），只是换到全站最重复的那个槽位：页首。
